肖志斌（嘉宾） (00:01:43)

这是一个非常好的问题啊。首先回答：是的。就是 AI 芯片的战场从芯片设计本身转向了这种系统级的设计，包括这种异构系统的软件的设计。那其实我过去 20 多年，有一件比较幸福的事情，就是说我自己做的事情一直是没有离开本专业，一直是芯片设计相关。然后更确切地说，其实就是软硬件协同设计和架构设计。我一开始在浙大本科读的是 EE（电子工程）。后面为什么去做这个架构和芯片设计呢？是因为当时上了这种计算机组成的课，然后计算机体系结构。包括当时有一个很有名的教授叫做 Yale Patt，他是发明 CPU 里面这种 branch prediction（分支预测） 架构的老师，UT Austin（得州大学奥斯汀分校）的教授到浙大去讲课，正好暑期我上了他这课。从此就喜欢上了 computer architecture（计算机体系结构）。

肖志斌（嘉宾） (00:02:50)

然后我直接，所有过去 20 多年做的事情，从本科研究生博士到加入 Oracle（甲骨文）去做啊 CPU 的设计，当时做数据库的加速芯片的设计，之后在阿里巴巴做含光 800 和 AI 芯片的设计，再之后创业做稀疏的 AI 芯片，到目前我做这家啊 AI 基础设施的系统优化公司，那其实一直做的就是一件事情：怎么样让系统变得更有效，让系统更高效的做计算。就一直是做同一件事情。我最早的话其实是做 DSP（数字信号处理器）处理器。当时是在浙大读本科和研究生的时候做的是单核的 DSP 处理器。那时候大概是在 2002、2003 年开始，当时有这种类似于 863 的项目，当时在国内要支持做这个自主研发的 CPU 和 DSP 处理器。那我有幸从本科的时候就参与了那个项目。然后在浙大又读研究生啊。当时在浙大读研究生，参与这种比较大的 DSP 处理器的正向研发工作还是非常少见的。

肖志斌（嘉宾） (00:04:05)

所以我们当时我的这个研究生的课题当时是在基于 MIPS（指令集架构），MIPS 是一种传统的这种处理器架构啊。基于 MIPS 处理器指令集上面做多媒体指令的扩展。最后这个 DSP 处理器是为了做，当时很简单，做那个 MPEG（音视频编码标准）是 VCD 的编解码，有语音跟视频的编解码。那这是我的研究生的项目。然后博士的项目呢，就在 UC Davis 读博士，那从单核的 DSP 就变成了 Manycore（众核）的 DSP。当时解决的一个问题是用 Manycore 的方式做流式计算，叫做 dataflow computing（数据流计算）。去做 communication（通信）方面的问题，还有视频编解码的问题，还有一些 big data（大数据）的查询和那个这个排序的一些问题。那这样在这种流式的结构上面，其实就是跟现在的所谓的用 AI 处理器的这种 dataflow 的架构很像。就是让数据在片上流，而不把数据放到这个芯片外面。

肖志斌（嘉宾） (00:05:20)

所以数据实际上是在很多的 Manycore 的在很多 core（核心） 的 DSP 处理器之间进行流动。然后每个 DSP 处理器，它的那个这个指令和 memory（存储器），指令和那个数据的 memory 非常非常的小。然后通过某种互联的方式把这些芯片连接在一起。那当时这个架构其实还是非常有先进性的。每个 DSP 处理器它可以 tune（调节）它的 frequency（频率）和 voltage（电压）。这是我的博士课题啊。然后之后在 Oracle 的话，就进展到我们在 CPU 里面支持这种数据库加速。那当时 Oracle 是买了 Sun Microsystems（太阳微系统公司），大概是在 2015 年左右。那我是 2017 年加入 Oracle。那 Oracle 当时我们要在还在做 SPARC（处理器指令集架构）处理器。可能很多听众朋友不知道 SPARC 处理器啊。

肖志斌（嘉宾） (00:06:11)

SPARC 处理器当时 SPARC 跟 IBM 的 PowerPC，还有 x86 是主要的几类大型的这种服务器的 CPU 的指令集。 SPARC 的这个服务器当时是几年之内不用关机。加上 Solaris（操作系统） 操作系统，它是非常稳定。Oracle 买了 Sun 以后呢，我们当时想做一些创新，那怎么创新？那 Oracle 的主业是做数据库。那我们就想在 SPARC 的处理器里面，把数据库的这些操作放在 CPU 啊的作为一个 coprocessor（协处理器）或者是一个加速器单元，跟 CPU 共享整个所有的 memory 带宽，这样可以 saturate（用满） 整个 CPU 的 memory 带宽，然后可以做 in-memory（内存型） 的数据库。我们当时有 TPC-H（数据库性能基准），这个可能做数据库人知道啊。TPC-H 是一个 Benchmark（基准测试），里面有 22 条 query（查询）。

肖志斌（嘉宾） (00:07:07)

然后我们当时是把这些算子硬化到啊硬件里面，然后设计一套指令集，然后设计一套 runtime（运行时系统），然后跟 Oracle 的那个 Database 去做这个对接。就相当于变成了 Oracle 的这个 query optimizer（查询优化器）的一个 accelerator（加速器）。你可以用这个东西来加速某些操作。那这在 Oracle 大概做了五六年这个事情。之后的话就是在阿里了，做给阿里巴巴做第一代的 AI 芯片。再往后的话就是上一家就是 AI 芯片公司，我们做稀疏化的 AI 芯片。到现在我们做 ZFlow.AI。那所有这些经历，最终我们是看到整个芯片，因为这个摩尔定律越来越慢，所以芯片 level 的这个单芯片的这个算力，性能的提升，或者是功耗的降低，其实都越来越变成了一个瓶颈。那瓶颈其实在系统层次和软件层次。

肖志斌（嘉宾） (00:08:10)

所以这也是为什么如果我自己做的事情不是瓶颈了以后，或者是已经有很多 AI 芯片公司在解决这个单芯片的问题，那我觉得我应该要去解决一个瓶颈，新的瓶颈的问题。新的瓶颈就在系统。所以这也是为什么我们创建 ZFlow.AI 这家公司。我们通过做架构的方式，架构仿真的方式，去指导 AI 芯片的设计，还有这种 AI 系统的优化。然后我们把模型的编译，runtime 的调度，还有 AI 系统的仿真合在一起，做成一个统一的平台这样。我们的这个客户在没有硬件的时候，他就可以去仿真各种硬件优化的方法。然后在特别是现在这些 AI 的这种集群越来越贵，越来越大，其实很多系统工程师他是没有这种硬件支持的，所以我们的这种系统仿真其实给了他们一个很好的一个工具去做系统优化。那带来的好处就是直接提升这个 AI 模型在硬件上面的这个效率。然后我们回答了一个非常重要的问题：就是到底什么样的模型跑在什么样的硬件上是最经济的？那这个硬件有可能是已经存在的，还有这个硬件有可能是不存在的。

肖志斌（嘉宾） (00:09:35)

我们通过仿真和自动 profile（性能分析），把这两件事情合在一起。所以回到刚才你的问题啊，就是确实，我们这个 AI 系统的瓶颈不在于 AI 芯片了，更多的是在于系统还有软件。

## 芯片如何从设计走到量产

月球大叔（主持人） (00:13:10)

那您刚才讲了嘛，您有可能也后边还会再去做芯片。就是我作为一个非常非常不知道芯片怎么做出来的人，就特别想了解一颗芯片到底是怎么设计和实现就是量产的？

肖志斌（嘉宾） (00:13:23)

了解其实芯片设计其实是非常的这个整个这个设计的周期是非常长的。像我们以前做 CPU 芯片，那基本上是两年设计周期，然后流片，然后最后系统加软件，最后要上线，可能要 3-5 年。那最近就是英伟达就把这个芯片的节奏这个带起来了，就是说每年甚至于一年出好几款芯片。那芯片一开始其实是说，就像建房子，我们要决定到底做什么样的芯片。你到底是做编解码芯片呢，还是在做这个通信的这个比如说 Wi-Fi 某一个标准的芯片，还是做比如 CPU GPU 相对比较通用？所以决定做什么芯片，那这个是实际上是市场驱动的。或者是你比如说你跟某家公司某家 hyperscaler（超大规模云服务商）这种云服务的公司，他看到了一个应用场景，他觉得比如说在有些云厂商啊他做编解码芯片，比如说有一些做视频流的这个公司。他这个挺有意思啊，就是说这是一个应用场景，就是每个人的手机的编解码能力都不一样嘛。

肖志斌（嘉宾） (00:14:34)

所以他的那个手机视频输入的时候，是各种五花八门的格式，然后他要通过一个 transcoding（转码）把它变成统一的格式存在那个服务器上。然后分发的时候，大家手机的性能又各有不一样，分辨率又不一样，又把这个格式又转成不同的格式那这个就是一个专门的芯片。那这就是先从需求出发唉，这有这么个需求。如果我用 CPU 去做的话，那非常贵。有甚至于 transcoding，很多 CPU 是不带这种编解码的能力的，所以你需要加很多的这个这个 CPU 服务器专门做这件事情。先从需求出发。然后需求好了以后呢，那就是架构师要入场了。架构师要啊这个我们叫做 PPA（功耗、性能、面积），power、performance、area（功耗、性能、面积），还有 cost（成本）这个 trade-off（权衡）。芯片到底做多大，然后有哪些功能，那这些功能跟竞争对手之间呢又有什么样的差距？

肖志斌（嘉宾） (00:15:35)

因为芯片这个竞争非常惨烈，就是说基本上第一名占了大部分的市场，那第二名占小部分，第三第四名只能喝汤，或者是甚至汤都喝不到了所以你可以还要去做竞争市场的这个调研，你的芯片一两年之后不能落后。这是架构师要做的事情。架构师最后出来一个芯片的 spec（规格）。再后面，我们这里面还有一个微架构师。微架构师就是把芯片的 spec，芯片的 spec 有可能是指令集，有可能是芯片 high-level（高层级） 的 block-level（模块级） 的这些结构。然后这些结构和功能定义好了以后呢，那微架构师就要出场了，怎么样去把它变成一个可以实现的硬件？因为同样一个功能，比如说我做一个编解码的这个 FFT（快速傅里叶变换），我有无数种实现的方法。那每一种实现的方法都有那个不同的 trade-off，那微架构师就进来了。然后架构师给他这个 constraint（约束），微架构师把它变成一个微架构。

肖志斌（嘉宾） (00:16:39)

肖志斌（嘉宾） (00:17:41)
