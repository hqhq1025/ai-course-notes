# L06 独立事实审阅

已审阅 `generation/prose.json` 全部 7 节、代码与练习。路径采用零起始索引。仅修下列具体错误，不要求再增加通篇警示。

## 必修：代码与机制

1. `sections[2].code.source` 第三段、`sections[2].units[6].reading`：以 `top >= stk` 判断非空、`ret()` 执行 `--top` 的写法，会在弹出最后一帧时形成指向数组首元素之前的指针。标准 C 不允许这种指针运算；常见的 `top = stk - 1` 初始化也有同一问题。应用整数栈深 `sp`，以 `sp > 0` 判非空、`stk[sp - 1]` 取顶帧，并明确容量检查。若保留原课件代码截图，正文应把它解释为课堂省略边界检查的示意，另给合法 C 实现。第二、三种算法也需 `n >= 1`，否则 `n == 1` 基线无法终止。

2. `sections[2].units[2].after`：POSIX `getopt` 支持短选项，不提供通用长选项或子命令解析。长选项常用 GNU `getopt_long`，子命令需另行组织。不要写成 POSIX getopt 可以包办“长短选项与子命令”。

3. `sections[3].code.source`：`legacy` 参数未参与任何分支，仍然无条件输出 `BITXOR`，因此并未实现旧版 Excel 能力适配。最小修正是去掉未使用参数，明确这是现代 Excel 的最小后端；如保留参数，应按目标能力验证并对不支持的算子明确拒绝或给出经核验的等价降级。当前示例也缺未知 Node 的显式错误分支，会默默返回 None。

4. `sections[3].boxes[1].text`：笼统声称 Excel 缺乏局部变量与循环，与同节推荐 LET 直接冲突。现代 Excel 有 LET、LAMBDA 及 REDUCE/SCAN 等机制。应限定为所支持的旧版或所选公式子集，并把痛点写成跨单元格依赖、版本能力与生成维护成本，而不是普遍缺少这些表达能力。

5. `sections[5].units[0].after`：Git 提交在逻辑上保存项目快照及父提交，不是每次只保存状态增量；diff 可以由快照比较得到，pack 存储可用 delta 压缩。应与 L03 的正确解释保持一致。

6. `sections[5].boxes[1].text`：将 Persistent Tree 与 WAL 合说成“每次不原地覆写旧节点”，再声称“状态、操作日志、Delta 在信息量上相互转换”不成立。WAL 约束日志先于相关数据页持久化，并不禁止数据库更新页面；单个状态不能还原历史过程，多种命令能产生同一状态变化，diff 也不能自动还原业务原因。可持久化树、WAL、事件溯源分别说明所保留的信息，删除可互转的无条件结论。

## 必修：教学表述的对象与范围

7. `sections[1].units[5].after`、`sections[1].boxes[2].text`：缺课次数 -1 的例子虽声明未查明根因，紧接着却声称“足以说明众多查询共同依赖字段假设”。多个页面失败也可能共享单个报错入口，观察本身不能区分。保留现象与“需追查跨模块依赖”的启发，不把传播路径写成已确认机制。

8. `sections[1].units[8].reading`：Brooks 的《No Silver Bullet》原始主张有“未来十年内、没有单一发展、数量级改善”等语境，不是证明任何年代都不可能有数量级进步的定理。可以说文章区分本质复杂性与偶然复杂性，讨论为何单一工具难以消除需求复杂性；不要用它否定尚未发生的所有 AI 能力变化。

9. `sections[4].units[3..8]` 与 `sections[6].units[5].reading`：批评对象是“只覆写当前结果且不保存依据的设计”，不是 CRUD 接口本身。CRUD 系统也可维护历史表、时态版本与审计依据；同样，仅在提示词中加入 CQRS/Event Sourcing 并不会自动记录规则版本与输入依赖。用准确主语直接说明这些设计取舍即可，无须每段补一条免责声明。

10. `sections[4].units[6].before`：混入日文“システム”，改为“系统”。
