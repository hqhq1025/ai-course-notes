## 教师讲解摘要

| 来源 | 要点 | 去处 |
|---|---|---|
| 第三方字幕：开场回顾与物理椅背类比；对应 slide-002 与讲义《代码便宜以后，什么变得更重要》 | 用教室里的椅背类比解释“软件不软”：物理椅背有弹性，靠上去瘪下去、站起来弹回来；而软件是纯粹的逻辑制品，具有严格形式语义，卫星上宇宙射线导致内存里表示长度 N 的无符号整数最高位翻转，或者数据中心高密度电路在热噪声下出现静默错误，都会让程序彻底崩溃或产生错误结果。 | 第一章 代码便宜以后，什么成为了真正的杠杆？ |
| slide-003；讲义《代码便宜以后，什么变得更重要》；第三方字幕：关于南大软工排名与定量研究的讨论 | 调侃“学校里的软工人都不在做软工”：尽管在 CSRankings 数论文数量可以排到前面，但大量学术研究集中在容易量化的编码实现或用神经网络做缺陷预测、推导关联上；而真正决定软件走向的需求、产品和架构极难做控制变量的定量实验，甚至如城市规划的 Wicked Problems 一样，连各方对“什么算成功”都没有共识。 | 第一章 代码便宜以后，什么成为了真正的杠杆？ |
| 第三方字幕：关于 Lab1 个人助手 Prompt 与技术债的讨论；对应 slide-004、slide-047 | 指出 AI 不会主动替你思考架构，但 Prompt 里短短几个字（比如要求做 CLI 还是 Client-Server，或者要求采用 CQRS）就会膨胀成完全不同的文件结构（如生成 `cli.py` 还是 `db.ts`），一旦写下就会进入 Agent 的上下文，成为后续所有需求迭代都必须背负的历史与技术债。 | 第一章 代码便宜以后，什么成为了真正的杠杆？ |
| 第三方字幕：需求工程同理心讨论；对应 slide-008 与讲义《教务系统为什么会陷入需求泥潭》 | 强调计算机专业学生做需求设计最容易缺少软技能“同理心（Empathy）”：不能拿 Geek 的习惯去揣测所有用户，必须去想一位 53 岁、还有两年退休、上大学时没摸过电脑的优雅教务员女士，她需要的可能不是复杂的炫技功能，而是字大一点、点鼠标时不容易误触旁边的按钮。 | 第二章 教务系统的需求泥潭与“没有银弹” |
| slide-010；讲义《教务系统为什么会陷入需求泥潭》；第三方字幕：2018 年上课第一天修改缺课次数的经历 | 分享 2018 年刚入职上课第一天使用老版教务系统教师端的亲身经历：绕过前端校验将一位同学的缺课次数从 0 改为 `-1`，结果系统中所有能查询出这位同学选课记录的页面立刻全部崩溃（返回 500），只能打电话向教务处报修；以此说明局部数据假设一旦被各处隐式依赖，单个特殊值就会沿依赖图引发系统性瘫痪。 | 第二章 教务系统的需求泥潭与“没有银弹” |
| 第三方字幕：离散数学拆课与读了六年学生的特批案例；对应 slide-009、slide-012 | 举例说明现实需求演化的冲击：把一门《离散数学》拆成上下两学期两门课后，原本只支持单选一门课的毕业要求下拉框瞬间失效，必须引入“或”逻辑并处理跨院系转专业课程抵扣；遇到读了六年只差这门课且当学期不开课的学生，教学院长线下特批抵扣后，若系统无处表达，工程师就只能直接进数据库改毕业状态。 | 第二章 教务系统的需求泥潭与“没有银弹” |
| slide-016；讲义《几行代码也有架构》；第三方字幕：关于 `getopt` 与批判“语言律师” | 批评“语言律师”式的授课（例如讲 C++ 新特性只写一个返回 `a + b` 的 lambda 就算讲完了），并以 POSIX 的 `getopt` 处理命令行 `argc/argv` 为例，说明哪怕在很小的程序里，把复杂的参数字符串解析隔成清晰的 parsing state，也是一种抵御需求变化的架构设计。 | 第三章 几行代码也有架构：从信息隐藏到十行汉诺塔 |
| slide-017 至 slide-022；讲义《十行汉诺塔背后的三种看法》；第三方字幕：对比 GPT-6、DeepSeek、绿导师与百度搜出的 CSDN 汉诺塔代码 | 对比四个版本的非递归汉诺塔：GPT-6 “不做人了”，直接用步号二进制末尾零个数的数学规律写出极短循环；DeepSeek 遵循人类经典语料用显式任务栈分解；教师本人（绿导师）从 C 语言小步操作语义出发构造带 `pc` 的栈帧状态机（甚至能推广到 F 与 G 相互调用）；而搜索引擎搜出的某篇高赞博客却写出了与 `std::move` 命名冲突、塞满分支的劣质代码。 | 第三章 几行代码也有架构：从信息隐藏到十行汉诺塔 |
| slide-024 至 slide-029；讲义《两千行二维码程序：原来我们需要一个编译器》；第三方字幕：Excel 二维码生成器与 Lisp 括号笑话 | 把直接用 Excel 公式写二维码生成器比作“最后一页全是括号的 Lisp 程序”或用 Brainfuck 写《毁灭战士》，指出 Agent 直接写公式会与不配对的括号苦苦搏斗，且一旦遇到 Excel 版本降级（如从 `XLOOKUP`/`LET` 退回旧版）或整体右移一格就会彻底崩溃；跳出问题看，本质上是缺少一个带有中间表示（IR）的 Python-to-Excel 小型编译器。 | 第四章 两千行代码的架构：把 Excel 二维码生成器看作编译器 |
| slide-036、slide-037、slide-038；讲义《计算机系变成计算机学院，ID 要不要变》；第三方字幕：南大系改院与博士期间研究生院教务系统故事 | 结合“南大没系啦”（计算机系改名计算机学院，导致 2011 年毕业记录若简单 JOIN 当前表就会变成毕业于计算机学院的荒谬结果）以及读博时隔壁组接手二三十万研究生院教务系统最终因扩招与培养方案频繁变动而沦为无法维护的“屎山”的故事，说明代码可以重写，但 CRUD 覆盖掉的历史依据连 AI 也推不回来。 | 第五章 五十万行系统的困境：CRUD 的有损投影与语义漂移 |
| slide-039、slide-040、slide-041；讲义《把历史保存下来：事件溯源》《恢复历史与按新规则重算》；第三方字幕：用可持久化数据结构与退学复学解释 Event Sourcing | 从数据结构课的可持久化树（修改节点时沿到根路径创建新版本并共享未变子树）、数据库 WAL 日志和 Git 出发，结合“学生因没买到 Token 退学、后来买到 Token 又申请复学”的诙谐例子，说明只要把事件历史作为不可篡改的事实保存下来，就能通过 Replay 重建状态，并严格区分“还原当年授予学位的历史事实”与“按今日新规则重算”。 | 第六章 把历史与依赖变成一等公民：事件溯源与重放语义 |
