## 教师讲解摘要

| 来源 | 要点 | 去处 |
|---|---|---|
| 课堂口述字幕（回顾与导引） & slide-002 | 教师指出上一讲逆向出的教务系统需求规格说明书虽然符合工程规范，但若不跳出需求看架构，直接“脑子一热”选个数据库百分百实现交付，从设计那一刻起就会背上长期的技术债；从 10 行代码到 50 万行系统，架构无处不在。 | 一、意图、规约与复杂性：需求与架构的职责边界 |
| 课堂口述字幕（需求与技术选型权衡） & slide-003、slide-004 | 教师用“文件系统（易配合 UNIX 工具 hack，但缺原子事务与并发控制）vs 数据库（提供 all-or-nothing 事务，但增加中间层）”说明任何实现决定都会引入附带复杂性；又用 Matt Pocock 的 `grill-me` 技能和“登录功能选型（自建用户名密码会牵出忘记密码、发短信/邮件泥潭；接微信登录又要企业资质和交费）”说明需求工程收缩意图空间时，每做一个决定都有连锁代价。 | 一、意图、规约与复杂性：需求与架构的职责边界 |
| 课堂口述字幕（读经典与小脑袋） & slide-006、slide-007 | 教师结合自己开车时用语音与大模型聊 1980–2010 黄金年代系统论文的经历，引出 Dijkstra 1972 年《Structured Programming》中的“我脑袋很小（small head）”，把人类比作“参数有限的大模型”，说明分层与“珍珠项链”抽象正是为了迁就人类有限的工作记忆。 | 二、尊重有限的“小脑袋”：结构化编程与概念层次 |
| 课堂口述字幕（OJ 动态规划调试痛点） & slide-008、slide-009 | 教师举例说学生写 200 行动态规划 `dp[i][j][k]` 一旦算错且不 crash 就无法调试，原因是思考时用到了有向无环图（DAG）状态空间，写代码时却把概念层次扔掉只剩三维数组下标；若把状态和迁移重新封装、打印可视化，调试完再改回高效形式，这就是在小程序里运用概念层次架构。 | 二、尊重有限的“小脑袋”：结构化编程与概念层次 |
| 课堂口述字幕（OOPSLA'98 演讲与编程语言架构） & slide-010、slide-011 | 教师展示 Guy L. Steele Jr.《Growing a Language》原件，解释其开头只能用单音节词、连 woman 和 machine 都得现场定义的表演设计；并对比极端最小却不可读的 Brainfuck、C 语言糟糕的 `qsort`（`const void *`）以及 C++ Boost 模板的滥用，说明好的设计不是在“小而简陋”与“大而臃肿”间二选一，而是设计让语言和系统能够“生长”的元规则。 | 三、生长的语言与开放的解空间：架构设计的品味 |
| 课堂口述字幕（建立品味与“大学毁灭计划”） & slide-013 | 教师批评长期刷 OJ 会把人训练成不考虑扩展性的“用后即扔”解题机器，而 CSDN 拼凑文章、“防自学教科书”和 AI Slop 正在污染品味；因此半开玩笑地提出“大学毁灭计划”——把 1970–1990 年代经典文献的原始智慧拆开重组来生成教材，鼓励学生带着问题读一手经典。 | 三、生长的语言与开放的解空间：架构设计的品味 |
| 课堂口述字幕（UNIX 组合性与现场演示） & slide-014、slide-015、slide-016 | 教师指出数据库查询隔着一层 SQL 间接层，而 UNIX 文本流让人和程序共用直接接口；并在课堂现场演示将命令行工具与选择器组合，为 `nano` 编辑器拼装出一个交互式“打开文件菜单”，说明从使用 UNIX 命令行那一刻起每个人都是通过组合创造新用途的程序员。 | 四、支撑通用应用的系统抽象：UNIX、关系数据库与 Internet |
| 课堂口述字幕（数据库与 Internet 的演进回忆） & slide-017、slide-019、slide-020 | 教师结合自己早年做程序合成研究体会到数据管理绕不开 Codd（1970）关系代数，以及学生时代用明文 Telnet 上南大小百合 BBS 灌水、用 FTP 断点续传下电影，到今天全面转向 SSH 和 HTTPS 的亲身经历，阐明 RFC 1958“唯一不变的是变化本身”与城市街道局部改建的架构智慧。 | 四、支撑通用应用的系统抽象：UNIX、关系数据库与 Internet |
| 课堂口述字幕（JSP 模板与 Prompt 工程类比） & slide-022、slide-023、slide-024 | 教师将 1990 年代末用 JSP 模板替代 Servlet 字符串拼接 HTML，与今天开发 AI 应用时用 Jinja2 模板留出 `instructions` 槽位而非用 `prompt = A + B + C` 硬拼字符串作类比；同时警告把代码直接嵌进 HTML 虽然方便，却极易诱发程序员把课程容量检查等业务规则顺手复制进每个页面。 | 五、面向客户需求的业务架构：从页面内嵌 SQL/JSP 到 MVC |
| 课堂口述字幕（前端搜索框痛点与 React/Vue 对比） & slide-027、slide-028、slide-029、slide-030 | 教师吐槽某些老旧教务系统在已经拿到列表时还要点“搜索”发请求查数据库，指出搜索过滤词 `query` 和鼠标 hover 状态虽不入库但也是 Model（即 ViewState）；并说明理想上希望把 DOM 写成状态的纯函数，只是直接全量重算几万个节点太慢，React（Virtual DOM 与状态快照）和 Vue（响应式依赖图与绑定）都是在底层帮我们隐藏性能开销、隔离状态与渲染复杂性。 | 六、界面状态也是状态：MVVM、Vue 与 React 的派生视图 |
| 课堂口述字幕（长流程静默损坏与个人记账系统） & slide-031、slide-032、slide-033、slide-034 | 教师指出在长流程业务中靠手改数据库或特批覆盖，往往会留下“风控失败却进入下一环节”“既能毕业又不能毕业”的静默损坏（silently corrupted）数据；并分享自己虽不懂会计法规，但采用“Event Sourcing + LLM as a Compiler”开发记账工具：把流水账交给 LLM 编译成带柯里化（`@Curry`）封装的确定性记账动作，再通过 replay 自动归约生成资产负债表、利润表与现金流量表。 | 七、跨越时间的长流程：复式记账、Event Sourcing 与 LLM 编译器 |
| 课堂口述字幕（查卷挂科连锁反应与 SQL 的十亿美元错误） & slide-037、slide-038、slide-039 | 教师用“学生坚持查卷导致老师原本救命的 20 分被扣、计算机系统基础从及格改判挂科，进而连锁影响操作系统先修资格、学分与毕业结论”的生动案例，说明只存当前状态（如数据库里存一列 0/1 表示能否毕业）为何脆弱；进而调侃 SQL 未把任意计算依赖作为一等公民是它的“Billion Dollar Mistake”，倡导只存 Source of Truth，把状态一致性问题变成可重跑、可推演未来的计算正确性问题。 | 八、显式数据依赖：从状态一致性转向计算正确性 |
