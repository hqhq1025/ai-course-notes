我干了什么呢？我在 Neovim 里按了 F5，然后打开了一个浏览器，我们就可以正式开始上课了。

今天我们站在一个非常重要的交叉路口。你们是 Computer Science 的同学，我们从你们刚进入学校开始，就会讲计算机发展的历史。在计算机发展史上，其实经历了很多次非常重要的变革。我觉得最主要的，是把昂贵的能力变成了日用品。

1975 年的时候，我们有了第一台 PC 机——Altair 8800，在图片的左边。这张图片也是 AI 生成的，你们可以看出有非常明显的 AI 味儿，而且它应该还不是一个特别强的模型。但没关系，我说过，我上课是跟大家进行比较松散的讨论和交流，之后我会把课程重新切片、再整理一次。

从 PC 到互联网，互联网连接了所有人。我至今还记得——你们没有经历过这个时代——那时我可能在上小学，快毕业的时候装了一个叫 ICQ 的软件。你们可能没听过这个名字，ICQ 就是“I seek you”，三个字母 I、C、Q。那时候腾讯的山寨版还叫 OICQ，后来腾讯把它改成了 QQ。那时你可以随机加到世界另一端的一个人。如果加到的是 native speaker，他会跟你说英语，一下子发很多，打得非常快，而你完全无法理解他在说什么。因为那时我们可能刚学一点英语，只会说“Hello”“Good morning”。

从互联网再到移动互联网，我印象很深：一夜之间，所有菜场卖菜的人都有了支付宝和微信两个二维码。在很短的时间里，移动互联网就改变了、并且一直在改变我们的生活方式。到了 2022 年，ChatGPT 和 AI 是人类历史上增长最快的产品。

在这样一个人类命运的交叉路口，我们该以什么方式上课、应该学什么，其实都需要思考。在这个背景下，我决定还是应该开一门 vibe coding 的课程。为什么呢？前一段时间，大家有一个说法叫“AI 替我上大学”。我觉得这个说法很对：老师用豆包出题，大家用豆包做作业，在整个闭环过程当中，只有学生没有受到训练。

现在 vibe coding 很厉害，所有作业都可以直接交给 AI。曾经，操作系统作业折磨大家，大家在痛苦的折磨中获得提升；现在不一样了，你直接把作业链接丢到 Codex 里，连复制粘贴都不需要。甚至都不需要告诉它链接，只要说：“蒋老师的操作系统课第八个实验，能不能帮我实现？”这就结束了。

所以，在这样的时代，我们该怎么办？到底还应不应该学编程这样的东西？答案肯定是既应该，也不应该。有些能力你还是需要的，但应该怎么做，我们不知道。我看到大家其实都处在一种非常焦虑的状态。

第一种焦虑是：AI 帮我上大学，上完以后我怎么什么都没学会？如果每门课都开卷考试，都是 AI 答题，我全都答对了，但出来以后却发现，我第一个就被 AI 取代了。

第二种焦虑是：我相信这里还有另外一些同学，可能延续了中学时很听老师话的状态。老师说什么你就做什么，每一堂课都认真听，每一次作业都认真做。四年毕业的时候，你发现自己被大学骗了。你的确学会了一些东西，但是这些东西 AI 都会做，于是你也很迷茫。

同学们现在最切实、最痛苦的事情，当然就是保研。你们向很多地方海投简历，我其实也收到了很多这样的简历，我觉得很糟糕。

这里有一份简历。首先，展示前的所有处理都是 AI 做的，我什么都没干。我只告诉它，我上课时需要展示这份简历，要把个人信息去掉。它把个人信息替换成了 Unicode 方块；如果复制粘贴，你会看到那是黑色方块字符。希望它把隐私都隐掉了。

这样一份简历看上去非常完美：有一篇 CCF 期刊列表上的论文，已经 accepted，还有在投的论文——当然，大家都说“在投就等于不存在”，因为你看不到。但这份简历对我来说是零分，因为没有额外的信息。它甚至没有 GitHub 链接，没有个人主页，也没有论文的 preprint。我不知道这位同学发生了什么，但对我来说，这样一份简历非常糟糕。

更糟糕的是，我收到过无数份这样的简历，你们的简历可能多多少少也是这个样子。这时你会发现，你和竞争者已经无法区分了：所有人都是一大堆实习、一大堆奖项、一大堆论文、一大堆在投。那什么能让你从这些简历里脱颖而出？如果刚才那份简历都被我认为是零分，你们应该怎样向未来的导师展示自己？

我相信在座的同学都非常焦虑。但好消息是，我希望用这门课缓解一下大家的焦虑，更多的是带大家找回一种快乐——vibe coding 的快乐。因为我在 vibe coding 中得到了很多快乐，而在这个快乐当中，你们又能在一定程度上理解软件工程是怎么工作的，做出一些有趣的东西，让简历显得更好看。对我来说，有一篇发表的论文可能是一个减分项，但对很多其他人来说可能还不是。

我讲了为什么要来上这门课，接下来讲讲这门课到底打算讲什么。这门课的题目叫“生成式软件工程”，所以它其实是一门软件工程课。软件工程做什么呢？做的事情很简单：怎样让软件工程不失败，怎样造出一个软件来。

我们经常听到一种说法：“作为人，和 AI 相比你的优势在哪里？你可以坐牢，AI 不能。”实际上，我觉得大学能教你的，或者说你大学毕业时能拥有的比较重要的能力，第一个是信息差。

信息差也不能说是人类社会可悲的一面，它是人类社会进步必须有的事情。你有别人不知道的信息，才能做别人做不到的事。所以学校里多多少少也会有这种恶性竞争。假想一个情况：你拥有一份往年试卷，别人都没有，那你就可以在竞争中胜出。这是你们身边的一种信息差，当然社会上还广泛存在很多其他不能说的信息差。

除了信息差以外，作为人的优势是你可以坐牢。但大学里真正应该教你的，是怎样成为一个更好的人，也就是你能够驾驭别人驾驭不了的东西。大学毕业时，你可以说：“我是一个更好的人，我有别人没有的能力。”所以这门课会试着帮大家建立驾驭人工智能的能力。

这门课怎么上呢？我希望采用以案例为主、比较松散的组织方式。如果你有兴趣来跟我讨论，想 challenge 我，说“老师，你这样做不对”，那欢迎来线下。如果你是听课型的同学，希望从这门课里获取知识，那我完全建议大家既不用到课，也不用看直播，因为今年我也想做一个非常有趣的尝试。

你们已经看到了，这是我的 slides。我按 F5 的时候可以播放，你可以看到 F5 播放的 slides 和刚才的 Markdown 有点不一样。我先把它关掉。左边是我上课之前写的讲义，相当于我会先想好今天上课时大概在什么时间讲什么、举什么例子，也就是约束好 AI 做什么。当你看到 F5 播放的 slides 时，会看到紫色部分，那是 GPT-5.6-sol 给我添油加醋、加上去的内容。

我有一个提示词，现在可以给大家看一下。这里有一个叫 make-slides 的 skill，我可以从自己写好的 Markdown 演讲稿里，让它添油加醋地做一些有趣的事情。

比如，我有一个类似于“我的 AI 耿同学”的 skill。我会让它生成三个 sub-agent，给它们赋予不同的 personality。他们有的人会干这个，有的人会干那个，在隔离的上下文里工作，最后主 agent 回来汇总。这样我就可以通过算力换智力：付出更多算力，就有更多智力。

我其实做过对比，换了几个版本的提示词。每个版本我都会重新生成一次，最终再让另一个模型做 review，盲评哪个版本生成的 slides 质量比较高。这样，我基本把它调到了一个质量相对较高的版本。你们看到的图片也全部都是生成的。

所以，我希望探索一条能够真正“杀死大学所有人”的路径。我认为，如果你是来学习的，会有更高效的方法。作为老师，我应该思考怎样以更好的方式把知识呈现给大家。我的答案是：上课是一种表演。比如说，我是个演员，要调动大家的情绪；上课时跟大家交流，并根据预先设定好的剧本完成一场演出。

演出结束以后，我需要做一件很重要的事：review 今天的表演。有时我举的例子可能不是特别恰当，或者回过头来，我想到也许讲另一个案例能让大家更加感同身受。因为我上课时有些部分是即兴的，而即兴就意味着不完美。

课后，我会把课程录像切片，重新整理成片段。因为我是从 content as code 来的，everything is code。我可以让上课的录像，也就是这次表演，重新回到 code 上，把它变得更丰富。这样不就实现数字永生了吗？我就实现了一门课程的数字永生。

你们看到的这套 slides，以及我的流程，都是按照 everything is code 工作的。这个世界里的一切都可以用代码生成，包括这个桌子。Computer-Aided Design，也就是 CAD，桌子、椅子、电脑都可以设计出来。

这套 slides 是怎么工作的呢？刚才的 Markdown 是 source of truth，其他所有东西，包括图片和幻灯片，全部都是 AIGC。我会用 agent 扩写选中的 snippet，变成 Markdown slides，再到浏览器里渲染出来。

我希望以切片的方式得到一个完美的程序。比如，我今天要讲生成式软件工程，它的要点是什么、逻辑是什么、第一节课应该怎么上，把这些沉淀成一个程序。这个程序现在也许由我维护；也许有一天我不维护了，比如我现在已经不再上操作系统课，我会把 B 站的操作系统课录像整理成这样的切片，然后由全世界的人来维护。你想定制什么样的操作系统课，就可以把它定制成什么样子。这不就把大学教课的方式全部颠覆了吗？

我觉得这是一条可能实现的路线，所以会在这门课上做一个比较轻的尝试，也欢迎大家随时给我反馈。

这门课的 policy 是：我希望重新找回同学们在大学时那种“上课耽误学习”的感觉。虽然你们可能还是要上课，但我推荐大家可以不上课，而是来这门课实践。我会带着大家实践，后面有很多真正实践的案例，让你们知道，在 AI 时代，学习方式变了，工作方式也变了，你们可以尽快适应这个非常有趣的时代。

我的要求是禁止古法编程。我相信你们个个都是古法编程的好手，因为你们要考试，马上要保研、要机试了。机试的时候，把你们往小黑屋里一关；你们看过我以前出的题，吓坏了，然后赶快去 LeetCode 上再刷一刷。

但我觉得总有一天，这件事情会改变。可能从上而下的传导不会那么快，因为改变一个体系很难，但是我非常想撕开一个小口子。

还有几个 policy。第一个，token 自费。本来我是想拉一些 token 赞助的，但看到选课学生的数量以后，我想还是算了。我也没必要拉着脸去跟他们要好多 token，比较麻烦。

首先我有个个人观点：如果手上没有付费 token，应该立即退学。当然，你可能确实不需要 tokenmaxxing。硅谷有一种风气，就是要拼命地烧 token，但你没有必要这样做。我在课上做的所有演示，除了 slides 是用一个更聪明的模型生成的——我觉得它能给我更好的质量——你看到的幻灯片、整个 lecture 里的东西，包括这些生成的 assets，全部都是 DeepSeek-V4-Flash。也就是说，我在这门课上会用一个足够便宜、但相对有一些智能的模型，来带大家完成这些事情。

我也知道大家都是夜猫子。作为 Computer Science 的学生，你们喜欢在夜里工作，而夜里用 DeepSeek 是比较便宜的。我建议大家在“梁文峰时间”用：白天你们要上课，等回去做作业的时候，正好就是“梁文峰时间”。所以 token 非常重要。每个同学都可以去 DeepSeek 充一百块，好像还可以。如果确实在 token 上有困难，可以联系我，我来帮助大家想一点办法。

还有一个很重要的 policy：我希望用“通过”或者“不通过”来评价这门课程。所以我在申请这门课程的时候，考核方式填的是“通过/不通过”。但教务反馈说，专业选修课一般不会这样做，通常只有“形势与政策”这样的课才采用“通过/不通过”。

但我觉得我们现在还不知道评判标准是什么。你可能用了更好的模型，就能得到更好的质量。同一个任务，让 Claude Fable 来做，就是比 DeepSeek-V4-Flash 做得又快又好，这没办法。我们也没有办法限制大家使用什么模型。那应该怎么评判？尤其是这样一门做 project、进行 vibe coding 的课程，我大概会给出一些建议项目，之后会更新到课程网站上。

例如，我建议你们实现一个自己的 email 管理系统，可以回复我的 email。我可能会用一个指定邮箱给你发邮件，你的系统可以把邮件回复回来。你可以尝试 vibe code 这样一个服务，让它运行在宿舍里一台一直开着的小电脑上。这就是一个比较不错的实验。有的同学可能会做得复杂一点，有的会做得简单一点；我可能会用自己的邮箱和大家的系统发邮件通信。

但到底什么叫做得好，什么叫做得不好，到底该给多少分？我觉得在这个时代，分数已经变得不那么重要了。真正重要的是，在你最后找工作或者保研的那一刻，投出的简历上面有什么东西。对你们来说，其实只有那一个考试。比较糟糕的是，为了能够走到那一刻，你还需要有一个比较好的 GPA，还得去 reward hacking，去 overfit 考试的题目。但最终检验你大学阶段成果的，是你交出去的简历能不能带你到下一个更高的平台。你敢不敢给 DeepSeek 投简历？他们的 bar 还是比较高的。

所以我最终希望，这门课结束后，大家能在简历里写：“我在生成式软件工程里实现了 A、B、C、D、E。”后面有很多链接，每个东西都做得非常漂亮；每一个你都能说清自己完成了怎样的设计和实现，它了不起的地方是什么。

我觉得最终有一种可能：如果每个人的电脑上都安装一个监控，我就知道你大学四年做过的所有事情，我的 AI 就可以评判你这四年到底度过了一个怎样的大学。当然，这是一件非常恐怖的事情，因为你摸的每一次鱼、看的每一部不想让别人知道的小电影，都发生在你的电脑上，它全都知道。我们不知道人类社会什么时候会演进到那个程度，但是要保持 open。这大概就是我们这门课的 policy。

课程开了一个头，接下来就可以进入技术性的内容了。首先讲一讲什么是大语言模型——今天其实不讲什么是大语言模型。大语言模型就是一个概率分布，和你们在概率统计课上学的抛硬币一样：已知抛了六十次硬币、加起来是四十，问第一次抛出一的概率是多少。你们在概率课上都做过类似的题目，没有任何区别。它是一个学到的概率分布。

给它一段很长的文本，例如给它一本书——当然输入可以是文本，也可以是图像。这本书到最后就结束了，但你可以在书后面再写几个字，比如“能不能帮我总结一下这本书”。接下来，大语言模型就会不断预测下一个 token 的概率。每次输出，你可以理解成它输出一个字符、一个字符、一个字符。这个模型很大，见过世界上各种东西，而训练它很难，所以现在的 frontier labs 才这么厉害。

但这门课站在使用者的视角。你们只要知道存在一个叫大语言模型的东西，可以打开 DeepSeek 的 Web App，问：“什么是大语言模型？我怎样体验它？”它会告诉你，你现在就在体验大语言模型。所以你不需要任何大语言模型的知识。

大语言模型是怎样进入我们的世界的？我第一次被大语言模型“按在地上打”，是在 2023 年 GPT-4 的时代。GPT-4 是一个幻觉非常严重的模型，当时我让它给我五岁的孩子解释什么是扫描电子显微镜。那个时候我们还在玩 prompt engineering，我给了一个大概这样的 prompt：“希望你用朴素的语言打一个合适的比方，帮助他理解这件事。”

有一天，我给五岁的孩子讲故事，不知道为什么讲到了扫描电子显微镜，我讲不下去了。GPT-4 给了我一个比方。现在展示的这个比方是 GPT-5.6 给的，我让它重新写了一遍：假设现在有一座山，你闭着眼睛看不到它的形状，但又想知道这座山是什么形状的，那怎么办？你就闭着眼睛朝山扔石头。朝有些方向扔，石头穿过去了；朝另一些方向扔，石头弹回来，你能听到声音。通过哪些地方穿过去了、哪些地方没有穿过去，就像 ray tracing 一样，你可以推测出这座山的形状。

小朋友大概听懂了，当然不可能百分之百听懂，但这个比方让我非常震惊。首先，模型有这方面的知识；第二，我后来特意查过资料，这个比方是对的。你看 GPT-5.6 给出了一个更严谨的答案，而且因为它有 reasoning，也给出了更好的解释。

在 GPT-4 的时代，我们会用 GPT-4 生成一些奇怪的东西。只用一个 prompt，就可以给 GCC/LLVM 找到一百五十个 bug。到了今天，在 GPT-5.6 的时代，这个工作完全就是一句话的事情，真的只要一句话，不再需要为 GPT 做任何特别的调整。

GPT 原本只是一个预测下一个 token 的概率分布。随着模型能够输出越来越长的文本，也能接受越来越长的上下文，Agent 就出现了：先有了推理模型，然后有了 coding ReAct 式的 Agent。

刚才的大语言模型可以输出下一个 token，那么我们也可以让它输出一个特殊 token，表示“调用一个 bash 程序”。这个 bash 程序运行后，结果会被重新送回 Agent，形成一个 loop。这样 Agent 就可以自主运行。你可以给它一个比较复杂的任务，它会不断尝试。

例如，我还是做了一些配置。你们看到我配置了 sway 窗口管理器，并针对课堂展示做了优化：对比度比较高，把顶栏等东西全部去掉，这样你们上课时可以看得更清楚。

我还做了其他配置。你们可能喜欢用 `top` 命令查看系统里的进程，如果不做定制，看到的就是比较朴素的 `top`；但我有一个更 fancy 的 `btop`。你能看到 OBS 还在浪费我的算力，也能看到内存还剩多少。我把它配置成了一个相对现代的终端。

你们还可以看到，我敲 `ls` 时，实际调用的不是 `ls`，而是自动把 `ls` 换成了 `eza`；当我要用 `find` 时，它也自动帮我换成了 `fd`。`fd` 的行为和 `find` 稍微有点不一样。`ls` 的输出也很 fancy：这是一个目录，这是一个 Markdown 文件，这是一个 Makefile，还有特殊的显示效果。

所有这些配置都是用 Agent 完成的。我只有一个 prompt：“你能不能帮我把现在的命令行终端和系统都配置成现代、比较好用的样子？”到这里就结束了，用的是 DeepSeek-V4-Flash，没有用更好的模型。

今天有了 ReAct 类型的 Agent，它就会不停地去 configuration 里修改。出错以后，它会尝试别的方法，最后能把任务完成。大概去年我上操作系统课的时候，Agent 还不太能用，会出各种错误，任务完成不了就停下来了。但到今年上操作系统课的时候，Agent 已经非常好用了。现在 Agent 产品爆发，到处铺天盖地都是 WorkBuddy 的广告，像 WorkBuddy、豆包的 Agent，都是这样的 ReAct 类型 Agent。

这个故事远远没有结束。今天你们已经感受到 Agent 非常强了，但我认为 Agent 的能力还远远没有被释放出来。我觉得 next-token prediction 是一种效率很低的模型。例如 diffusion model：我可以让它生成一段关于“Write an AI Slop”的内容。你观察它的过程，会看到它从随机噪声开始，就像 diffusion 生成图片一样，一点一点生成很长的内容。

它像人做梦一样：在梦境中，一点一点把某个东西想得、看得越来越清楚。未来还有很多可能性，比如 diffusion 类型的语言模型，甚至不再只是 predict next token，而是可以回过头去修改上下文，随时把很长的上下文裁短。这些都是今天很多人在研究的东西。

现在的模型已经非常强了。如果三个月后又有新的突破，模型会变得更强；一年以后模型再次突破，又会变得更强。整个 AI research 都在赌这件事情会发生，摩尔定律还在那里。我现在很难想象未来会变成什么，也不能预测最终会是哪一条路线、哪一种模型胜出。但可以预见的是，这个世界肯定会变得非常不一样。在这样的世界里，我们应该怎么办，是每个同学都值得好好考虑的问题。

吓唬人的事情说完了，我们可以吸一口气。我来告诉大家，实际应该怎样操作 Agent，这仍然是这门课主要要讲的内容。

首先，我站在普通人的视角给大家科普一下，暂且假设大家还不太会用 Agent，除了“帮我把这个作业做了”以外，不知道还能怎样用。从我上学期批改大家期末考试题的情况看，好像确实如此。期末有一道题是：“如果你要用 Agent 给我的课出一份期末考试卷，应该怎么办？”我发现大家使用 Agent 的方式可能需要我来稍微解锁一下，也可以和大家一起探讨。如果有特别好的想法，可以随时打断我。

首先，作为 AI Native 的一代人，你们要知道：给它一个合适的指令，它就可以把这个指令完成。我在课上选的是 pi，你只要跟它说就可以了，并且可以写一些配置文件，比如 `AGENTS.md`。

你可以问它：“你是谁？”你看，它还说自己是生成式软件工程的教学辅助 Agent。那你可以问：“你不就是个模型吗，为什么还知道生成式软件工程？”你可以自由、任意地问它。

它回答了。你看，它之所以知道这门课，是因为看到了仓库里 `AGENTS.md` 的配置，这部分是临时的记忆。所以使用 Agent 的第一个原则是：开始，现在就开始用；第二个原则是：随时问它。这是最基本的原则。

在这个意义上，其实是你的想象力限制了你的 agent 的上限。正好一会儿课间的时候，大家可以想一想：你用 AI agent 做的最酷的一件事情是什么？想象力是你们的上限。

我的第一个例子是今天上课用的这个系统。刚才我给大家展示过，所有的配置、安装都是由 AI 完成的。一直以来，我上操作系统课的一个特色就是带一个 U 盘，里面装一个 Linux 操作系统，可以直接插在教室的电脑上启动。你们可以看到，这是我的 U 盘，这是电脑的硬盘。有一年上操作系统课时，我把这个硬盘抹掉了，结果下一位老师上课就遇到了教学事故。为了展示操作系统原理，装机是件很痛苦的事情。

我曾经是“装机仙人”。这里有个知乎链接，那还是 pre-LLM 的时代，2021 年 7 月，我会做各种定制、各种定制系统。现在“装机仙人”已经彻底被 AI 取代了，因为我只用了一句话：“你去 mirrors.nju.edu.cn 上找一个 Debian 13 的镜像，把它装到我的 U 盘上，确保这个 U 盘可以启动，然后用模拟器验证。”

点睛之笔是“用模拟器验证”。我当然有相关知识，所以知道它是怎样完成安装的。它装完以后，真的在 QEMU 里启动，看到登录界面，并告诉我确实可以登录。我要创建的用户、用户名和密码，它全部做好并验证完成后再交付给我。

接着我启动这个 USB 镜像，告诉它我要装一个 tiling window manager。你们看到我现在操作得很顺滑：比如按 Super+Enter，它就会在右边产生一个新窗口；这和你们使用窗口的方式不太一样。我也可以按 Super+Space 把它挪出来。不会用怎么办？你可能在某个 B 站直播间看到有同学在用一个很酷的东西，却不知道怎样使用。我直接让 DeepSeek-V4-Flash 给我生成了一份文档，请它查看我系统当前的设置，告诉我各种事情应该怎样做。

它告诉我，Super+Enter 是打开 terminal，Super+D 是打开 app launcher。比如我按 Super+D，就可以打开 OBS 或 Chrome Browser。所有文档，包括你们看到的终端和 Neovim 的现代配置，我没有看过任何一眼配置文件，所有一切都是通过自然语言完成的。我只是让它保交付，我要什么，你帮我再检查一下，就全部完成了。

我觉得自己毕生的修炼，作为一个教 computer science 的老师，大四时就和你们差不多大，那时我已经在看英特尔几千页的 CPU specification，研究每个 CPU feature 是做什么的。到了现在这个时间点，突然有一个人可以和我沟通，它把这些东西全看过、全懂、也全能做，而我需要做的是解锁它的能力。

所以今天学习知识的方式已经变了。更多时候，你需要知道它能做什么，感知到它能做什么、能做到什么程度，然后带着它去做一件更大的、它目前还做不到的事情。人现在唯一的功能，就是带着 AI 去做 AI 目前做不到的事情。一旦你没有这个能力，就已经被淘汰了。所以没有 token，就可以立即退休了——这是我自己的观点。

首先，agent 彻底突破了 computer science 中“学习曲线太长，所以不想用”的瓶颈。你们可能都配置过漂亮的终端：看到 B 站上有人用花里胡哨的终端，自己也想搞一个，结果稍微改一点就出错，改一处 `.zshrc` 就出错，非常痛苦。有了 agent 就一点也不痛苦，它不仅可以替你改，还能事无巨细地解释为什么要这样改。你有什么新想法，一提它就说“好好好”，还可以给你提供情绪价值。

我前几天在小红书上发了一个帖子，说 token 为什么比学生好用，因为可以骂它，它不会还嘴。我肯定不能骂学生，但是可以骂 agent。所以，谁掌握了 AI agent，谁就掌握了暴增的学习效率。现在的学习方式应该是先用好它，先把东西搞出来，再回头复盘、理解。这个效率会比你从零开始一点一点搭积木高很多。这里面也有一个危险：你的理解和比较好的理解之间可能存在差距，但这是一个非常不一样的事情。

第二个例子是收发邮件、写草稿。我有一个自己的 skill，就不展示了。我的数据库里保存了我过去回复过的所有邮件，所以每当我收到一封邮件时，它会自动把邮件变成已读状态，并用我的口吻帮我写好回复草稿。虽然我觉得它现在做得还不够好，除了一些简单的 routine 性质的内容可以直接使用它的回复，大部分时候我还需要修改，但我已经得到了一个 AI bot。它也会处理邮件中的重要附件，例如收到发票时，会自动把发票保存到指定的归档位置。这些都是我预先写好的 instructions。

我还可以像你们使用 OpenClaw 或 Manus 一样使用它，不过我用的是 Apple 自己的 Reminders。我可以找到手机，在提醒事项里加一条：“帮我把今天的发票打印出来。”我现在就可以做这件事，代价无非是浪费一张打印纸。

我在一个叫“bot”的列表里增加一项：“把我收到的上一张发票打印出来。”只要点一下勾，它就 commit 了，我也就多了一个 todo 事项。这和你们在 Telegram 里跟 bot 聊天一样，之后只要等着就行，它会在后台处理。完成以后，它会重新给我一个推送通知；这个通知会通过 Reminders 送到手表上，告诉我已经可以去拿打印好的发票了。所有我放心交给它的日常事务，都可以让它处理。

我觉得这种方式比 Telegram 聊天框更好，而且流程会不断进步。我在 OpenClaw 出现之前就已经这样做了。我不认为 OpenClaw 或 Manus 是个人 agent 产品的终极形态，这类产品还可以做得更好，未来还有很多空间。

你们还在读书吗？还看书吗？还看论文吗？看论文痛苦吗？大家都在笑。我是一个很喜欢看书的人，在你们这么大的时候，每年仅教科书就要看几十本，还会看很多闲书。但我今天已经不看书了。为了上生成式软件工程这门课，我还是买了一些书，也带了几本来。这些都是我读书时仔细看过，甚至不止看过一遍的书。

这本是 Fred Brooks 的《The Mythical Man-Month》，也就是《人月神话》。这个中文标题非常 misleading。首先，什么是“人月”？你们会想到人和月亮吗？是每到月亮出来时就会变成狼的人吗？其实 man-month 很好理解，就是一种人力单位。其次，“神话”也不对。你们想到的神话可能是盘古开天地，带有美好的意味。其实这本书应该叫《人月鬼话》，因为“人月”是一种鬼话。

还有 John Ousterhout 的《A Philosophy of Software Design》。这本书非常紧凑，感觉比我当年看的英文版还要紧凑一些，里面有很多真正的软件工程智慧，非常好。我又重温了一下当年读书的感觉，读了第一章。读完第一章以后，agent 就启动了。

我会怎样读书呢？大概是在这个 skill 的这一部分，我的 AI 耿同学会比 GPT-5.6 Sol 更强一点，也会更 harsh 一些。为了制作每一页 slides，我都会先让 GPT-5.6 回看人类历史：在人类历史以及与我所讲内容相关的案例里，有没有一些 lessons、重要案例，能够给出启发和印证？第二，根据我讲的内容，能不能找一些相关工作，而且不仅限于 computer science。我会让它优先选择 very recognized、high-impact 的 resources，因为我要上课，希望给大家讲一些经典的东西。

还有 thinking from first principles。在我的 AI 耿同学里，我设置了更多这样的 personality，还有随机性，会进行“抽卡”。抽完以后，不同 agent 会讨论，产生有分歧的观点；讨论以后，我的主 agent 会把这些分歧的观点再送回给它们讨论，直到收敛为止。所以我有一个“算力换智力”的 loop，这样我就可以用它审稿、读论文。

如果我要 review 或阅读一篇论文，我会要求它从人类已有的知识开始，假设人类已有的所有东西都已经固定下来、都是已知的，然后把这篇论文里新的、最少的那部分剥离出来。这样一篇 12 页的论文基本上就没有剩下多少，会变得非常短，所以我现在读论文的效率非常高。

而且我会和它 chat。我会同时拿着论文原文、总结和深层次的总结与它交流。因此，我现在读一篇论文的效率比以前高得多。我仍然是在读论文，不是那种只看微信公众号的老登；我先声明，我不是靠看微信公众号学习的那种人。

我的发票已经打印好了。你们可以看到我收到了一条通知，叫“发票已打印”。我只要回到打印机那里拿走就可以了。所以它可以干任何事，literally，我那台电脑能干的事情，它全都能干。如果我有时间，或者大学倒闭了，我就弄一个机械手，让它能做更多事情。现在还做不到，但它已经可以操纵我的打印机。

AI 耿同学就在这里。我不仅用 AI 读书、读论文，还用 AI 上 B 站。当然，如果你上 B 站是为了娱乐，比如看“华强买瓜”的衍生视频，那就不要用 AI 了。

我是怎样“读”B 站视频的？给我一个 BVID，比如这是我上学期的课程，一个小时二十七分钟。一般来说，我会读 podcast，比如说 Matt Pocock 又发了一期讲软件工程实践的内容。其实我觉得他也有些“神棍”，有些经验不完全适合我们的课程。

我会把视频整理成自动生成的图文时间轴。你们看，这是整理过的文本，质量还可以，比字幕质量高一些，这就是全文。图文版的图片会稍微少一些，实际上我截图的密度会更大：当两帧图片之间的间隔大到一定程度时，我就会截图，由此得到这个视频内容的 ground truth。

这时 AI 耿同学就可以上线，为我消化一个多小时的视频。因为它有我的记忆，可以去掉我认为不需要看、很 trivial 的东西。例如，这里面所有内容都是我非常清楚的，我就不需要再看。去掉以后，我可以在几分钟内看完一个两个小时的视频，而且基本确信自己很好地掌握了其中不同的东西。

所以这是一件非常可怕的事情。在 AI agent 时代，会用 agent 学习的人和不会用 agent 学习的人，学习效率的差距是十倍、百倍。你们坐在这里，怎么和效率高十倍、百倍的人竞争？这就回到我一开始关于简历的问题：如果所有人的简历都一样，那么接下来你会想，那个还没有把简历给你看、学习效率是你一百倍的人，他的简历是什么样的？这是一个非常可怕的事情，而更可怕的还在下一节课。所以我们课间休息一会儿。

你们可以想一想。因为我还没有公开接下来的内容，想给大家留一点惊喜，下一节课我再讲比刚才更可怕的事情。所以我为什么要说“大蛇丸”和“人类完了”？你们总觉得我神棍，但我确实是这样想的。而且我非常确信，世界上肯定有人做得比我更好。我只是一个上有老、下有小的人，没有办法投入全部时间。比如上学期为了上操作系统课，我花了很多时间；如果不上这门课，这些时间本来可以用来探索怎样把这套东西做得更好。

我们回来。刚才直播时出现了一个非常好的案例：我的 USB 摄像头卡住了。教室里的系统大致是这样的：它有一个视频采集卡，信号可能从网络或别的地方传来，这边还有好几台机器。我不知道为什么学校用了成本这么高的方案，我觉得花五百到一千块钱应该就能解决整个问题。采集卡接入以后，它的 USB 连接断开了。大家可以看到，我在左边挥手时画面会动，但是 USB 那一路断掉了。

我刚才立即让 agent 修了一下，直接给了它一个 prompt。它说：“我先看看系统的 USB 设备情况，找出设备。”我告诉它 USB video 有问题，问它能不能 reconnect。这是 DeepSeek-V4-Flash，它使用了一些你们前所未见的 Linux 命令。有些命令其实我有概念，但也不知道具体怎样工作。反正它通过软件把 USB 采集卡“拔出来”，又“插进去”。那个接口在机器后面，我碰不到，它替我拔插了一次，然后就好了。如果视频再出问题，请大家打断我，我再重置一下。

刚才展示的还不是 AI 真正的形态。作为普通人，你从一个白板状态的 pi 开始，什么都没有：在 pi 的官方网站把它安装下来，再配置一个 DeepSeek-V4-Flash 的 API key，立即就能得到刚才展示的所有能力。这已经是很可怕的一件事，但 agent 远不止于此，它能拥有一个完整的生态系统。

当你有一个领域特定的任务时，根据计算机科学的一条定律——我上课时一直会讲这条定律——如果一件事情合理，并且你想做，那么百分之百也会有别人想做。在 pre-AI 时代，开源社区多多少少会公开一些脚本：有人把新脚本发布到 GitHub 上，你拉下来就可以用它做自己的事情。在 AI 时代，复用别人的能力变得前所未有地轻松。我可以在 SkillHub 上发布一个 skill，你也可以在 pi 的插件生态中找到插件。

那么，作为普通人，下一步应该做什么？应该用插件把浏览器管控起来，再用插件把电脑管控起来。

浏览器是一个非常出色的工程产品。我们用的 Chrome 可以说是人类软件工程史上的奇迹之一。它非常复杂，看起来只是一个显示网页的浏览器，代码量却远超操作系统内核，因为它要和用户打交道，有大量图形栈、显示相关的功能和性能优化等。浏览器本身就是一个软件工程奇迹，它有专为开发者设计的接口和 Chrome DevTools，你们应该用过。

比如打开 Chromium 后按 F12。你们可能都改过网页：很讨厌页面上的某个东西，就选中后按 Delete 把它删掉，它在当前页面里就没有了。你也可以在这里调试网页。一般网站还会在 Console 里嵌入招聘广告，同学们应该见过。比如上 B 站后按 F12，我记得 B 站也是有的。在这里可以看到很多信息，比如 HTTP headers 等。还可以把一个请求 Copy as cURL，连同浏览器的 cookie 和所有状态复制出来，再用 `curl` 命令发起请求并取得列表。

这些都是 pre-LLM 时代开发者做的事情，但在 LLM 时代变了：普通人也能享受到 Chrome DevTools 所有强大的能力。

我记得 2020 年我们做过一个非常疯狂的 project。大家都知道 Android 应用可以用 Java 写。假设有一个 Java 应用，Java 或 Kotlin 都会被编译到 Java 虚拟机上，我们就可以在 OpenJDK 上运行一个 Android app。运行时，系统会计算界面上所有按钮的 bounding box，也就是坐标，并知道按钮上的文本。但我们不走 Android 的那套渲染，而是直接在浏览器里呈现。你可以在 Chrome 的框里看到一个计算器，每个按钮都在，文字也正确；点击以后，计算器的状态会改变。也就是说，我可以在本机执行一个 Android app。这是一个非常 powerful 的工具，但今天不讲这个。

我们来做另一件事。你们都讨厌教务系统吧？我也很讨厌。我之后讲软件工程时，还会专门把教务系统当作软件工程的反面例子。

我先用手机扫码登录，希望不会暴露隐私。比如现在我的教学周历是空的。刚才我在 pi 里让它帮我打开浏览器，这个浏览器是属于 pi 的。你们能用它做什么呢？我很讨厌动不动就让我们填东西，所以我要让它替我填。

这时候，豆包输入法的含金量又提升了。我做这些日常任务时，会按一个键打开豆包输入法，直接和它对话。当然，这台 Linux 没有豆包输入法，我似乎也没有配置语音输入，因为声音输入可能有点麻烦。

我给它的指令是：“现在教学周历是空的，帮我用随便什么 AI slop 填起来，不要看任何东西。”因为当前目录是这门课的 repo，如果它知道这是哪门课，就会读取我的 lecture notes 等内容，但我不希望它去读。你们看，它还是在做这件事。我就是想让它填 AI Slop，它就是不听指令。这是 DeepSeek-V4-Flash 的麻烦。翻车也是经常有的，说明模型能力仍在不断增长。如果使用最一线的模型，它会更好地遵循指令。我在课堂上使用 Flash 的另一个原因是它更快。

不过没关系，这就是 agent。你能看到它的过程：它会不断反思自己做的事情是否合理，然后找到应该怎样处理。看起来像翻车，其实它刚开始只是在尝试；尝试以后，它找到了正确的方式。

所以 Chrome DevTools 是非常强大的工具。它最终发现，直接注入事件的方式不行，但点击鼠标可以。然后它已经开始填写 AI slop 了，我完全不需要值守，让它随便填点什么就可以。Yes, I love it. Doesn't matter.

它能力真正的边界在哪里？当它走通过一次以后，这个 session 里的东西会保留下来。我可以把它沉淀成确定性的脚本，也可以让它形成记忆，记录这条路径应该怎样走、什么能成功、什么会失败。它还可以把走过的这些网页全部变成脚本，于是你就得到了一个自动选课、抢课的系统。这是多么恐怖的一件事：你不需要任何知识，它就在这里替我填写 AI slop。如果本科生院一定要我填，我就用这种方式来应付。

而且，这其实是一整个生态，不只是一个典型案例。今天我讲了很多“还可以这样用”的例子，每一个都很厉害。我是教操作系统的。UNIX philosophy 能够成立，是因为管道可以让所有程序自由组合、无限复用，使一加一大于二。

刚才所说的所有东西也是如此：从一个上下文中提取记忆和脚本的 skill、浏览器 skill，以及在网页上进行浏览的 skill，都可以组合起来并互相调用。所以，现在 AI agent 的生态其实已经到达了一个临界点。你们马上会看到，这些东西的组合能把个人能力放大百倍、千倍。

对于一般人来说，他可以找到世界上各种各样的信息源。我不知道你们有没有订阅橘鸦的 AI 早报，每天早上起来刷牙时听一下，反正内容也是 AI 生成的，但它有 RSS 推送源。此外，还有 B 站推送、arXiv 推送、Hacker News 推送。这些事情我都可以做一次，再沉淀成 skill 或脚本。

这样，我就可以建立一个信息处理系统：大量信息源进入处理系统，处理系统最终产生有用的知识。这个系统由各种各样的 skill 构成，都是自然语言，一行代码都不用写，却可以复用。你会不断调整工作流，它则不断产生对你有用的知识，你的飞轮就转起来了。

想象一个拥有这种飞轮的人，以及没有飞轮的人，两者之间的差距是多么可怕。到这里，你就可以理解为什么 OpenClaw 和 Manus 是现象级产品，为什么它们能给人这么多惊喜，比如自我进化的能力。

虽然作为一个 CS professional，我其实并不惊讶。我尤其不喜欢让产品自动总结 memory，因为它有自己的提示词，可能把我不想让它记住的东西记住，却不记我想让它记住的东西。所以更多时候，我会调用自己的流程，明确告诉它把某个东西写进我的数据库里，让 AI 完成这些事。

但也许有一天，正因为现在的产品还不够成熟、模型还不够强，当模型越过临界点以后，我现在比 AI 多出的那一点点能力也会被 AI 取代，我也就被消灭了。

从这个意义上，你可以想到很多更有趣的事。比如刚才所说的录屏：你把自己一天的操作录下来，让 AI 自动改进你的流程，再问它：“我这一天做的这些事，还有没有提升空间？”很有可能，尤其大家还处于初学者阶段，会有很大的提升空间。

你们这一代人在 AI Native 环境下长大，才是未来有出路的一代。像我已经被迫处理很多事务性的事情，没有这个机会了。虽然现在还没有完全准备好，但我真的很难理解，为什么有些“旧人类”，尤其是老登，还能心安理得地每天做重复的事情。

当然，刚才的演示似乎出了些小问题，但 doesn't matter，我只要让它修就行。这显然说明我需要一个更好的模型。但我不理解，为什么有些人没有意识到时代已经变化。可能从公众号获得消息，和真正第一手使用过以后产生的感受很不一样。这个时代已经来了，所以我们需要认真思考这个问题。

这是普通人的视角。接下来是我的视角，也就是作为一个 Computer Science 从业者的视角。如果你们只是用 agent、Codex 把操作系统作业做了，那真的太小看它了。我们是 Computer Science 的人，非常清楚编程能力的边界在哪里，这其实就是我们和一般人的区别。

一般人很容易提出一个需求，但 agent 可能做不好、做不了，或者他不知道应该怎样 prompt agent，让它确定、快速地完成。而我们知道怎样把需求编译成可以复用的东西：什么应该以代码的形式复用，什么应该以 skill 的形式复用。我们会非常清楚。

我举个例子。有件事如果由一般人和 AI 协作，可能目前 AI 还做不到。我改完卷子以后要统分，一般来说这个任务会交给助教：“你去把分加了吧。”然后助教掏出计算器，算 12 加 13 加 14 加 15 加 16，再仔仔细细核一遍。我觉得我对学生太好了，这样也不行。

今年我尝试了这样一条流水线。第一遍，我先 vibe code，让 AI 写脚本和测试，测试流程跑完以后，再一次把它跑完。我的办公桌上有一台自上而下拍摄的摄像头，它会拍到试卷上的一个固定位置。我先把位置调好，然后按一下回车，它就拍一张照片。拍照后，程序会在后台用 Qwen 识别姓名、学号和每一项小分，再向文本文件写入一行。

所以，我处理一张卷子就按一下回车，再换一张卷子、再按一下回车，两只手都没闲着。如果卷子没摆好，我可以调整以后再来。第一个阶段完成后，第二个阶段按相反顺序处理。这时我的左右手换过来：左手按回车，右手拿笔。

按下回车后，程序会用语音播报学生的姓名、学号，以及每一项小分，比如 11 加 12 加 13 加 14 加 15。它一边报，我一边检查，因为 OCR 会出错，我不信任它；我要对班上的每一位同学负责。检查没有问题以后，我就把它播报的最终分数抄到卷面上。

最终分数是脚本用 `eval` 算出来的，所以不会因为大语言模型的幻觉而算错。我没有让大模型做加法。每一个分数我都亲自看过，最后分数会自动汇总到教务处的 Excel 模板上。我再上传 Excel 文件并抽样检查，确保没有问题以后提交。

因为我是 CS professional，所以知道边界在哪里。我知道本地有一个 Qwen3.8-27B，可以用 Ollama 运行；也知道应该采用这样一种最舒服的流程，减轻我和 agent 之间同步的代价。可以看到，这种流程配合豆包输入法会更方便。一般人即使用最好的模型，直接告诉它：“我已经改好了 140 张卷子，小分都写上去了，现在要统分，帮我实现。”它也无法这么快收敛到这个方案。

所以有些时候，人和 AI 现在还需要共建。但我也赌有一天 AI 的能力能够强到感知我的一切，帮我做出一个完美的东西。

现在可以回到软件工程的话题了，毕竟这是生成式软件工程。我们来做一个小的软件工程产品。之所以选择它，是因为大约一个星期前，我们在群里闲聊，说机器被管控很讨厌，于是想到一种情境：假设你在一家金融公司里，数据可以带进去，却不能带出来。比如插入 U 盘，可以把 Word 或 Excel 文件拷进去，但是任何文件都无法再拷出来。

机器受到管控，不能执行任何不受信任的程序，也不能显示任何不受信任的网页。你唯一能做的，就是从远处悄悄摄屏。但如果你想把一个很大的文件偷出来，该怎么办？这是 Computer Science 的人才能想到的事情。

我做了一个程序，这是一个典型的软件工程任务。这里有一个二维码，我可以把任何文件的内容放进去。比如当前文件内容是“Hello World”，内容改变后，二维码也会改变。你们可以扫一下，这个二维码没有危害，应该不会封号。扫出来的是以 `0001` 开头、经过 Base64 编码的字符串。

它也可以处理非常长的字符串。比如有一个很长的“Hello World”，我可以把它编码成二维码动画。动画里有帧号，按 F9 刷新后，就会看到二维码动画。也就是说，你只要偷偷摄屏，把循环播放的每一帧都拍到，就能把这里的数据偷走。

我使用的是完全合法的方式。注意，这是 Excel，Excel 是合法的，所有内容也都是公式。这里全部是合法的 Excel 公式，而且使用的都是 Excel 2019 及以前版本兼容的公式，它们把二维码绘制出来。这只是一个例子。

作为 CS professional，你可以用这种方式把数据偷出来。如果机器里能够安装 EXE——当然一般不行——还可以通过抖动鼠标传输数据：在上下维度抖鼠标表示 0，在左右维度抖鼠标表示 1。通过远程桌面连进去，就可以向里面传输数据；用二维码动画，则可以向外传输数据。

这样，只要有远程桌面，就可以在里面做一张虚拟网卡，把远程桌面变成虚拟网卡，再与它连接起来。你是 Computer Science 的学生，上过操作系统和计算机网络，知道这里需要哪些组件，就可以把它 vibe code 出来。AI agent 可以做到这些。

这是一个有意思的例子。刚才的 Excel 是用 AI 生成的，你的想象力限制了你能做什么。

总结一下，作为一般人，可以用 AI 学习、看书、做总结，实现信息处理的闭环；还可以使用 computer use、browser use，去做日常里的任何事情。同时，因为 everything is code，我可以用 AI 生成你能看到的所有东西，包括视频和论文。

我正在和一位同学做一个名为 VibeFab 的项目：输入自然语言，3D 打印机就可以打印一个东西出来。这个东西也是 code，由 Python 代码生成，所以能够实现从 bits 到 atoms。这个未来已经来了。AI 的能力只会变强，不会变弱。下一个问题就是它什么时候来，以及我们应该怎样面对它。

关于如何面对，我们可以进入生成式软件工程最重要的内容了。刚才建立了一个思路：“我三观尽毁了，时代的车轮来了，我已经被压在车底下了。”不用着急，AI 也不是完全完美的。

在 LLM 之前的时代就有一个老梗：“idea 都有了，就差一个程序员了，我们去挣一个亿吧。”商学院的同学可能跟你们说过。还有一种说法是：“A、B、C、D 轮也都有了，就差一个天使投资人了。”但没有人投资我们，事情没有那么简单。

首先，AI 很强，我展示了 AI 可以做什么；但是产品是一项系统性工程。假如要做一个外卖网站，就要处理前端、后端、交互、运营，整个流程中任何一个环节做不好，产品都会直接暴毙。虽然 AI 可以做每一项：它能设计，能做前端、后端、交互，也能运营；它看过世界上所有的书，什么都知道。但如果组织不好，产品还是会立即暴毙。

实际上，我在 `QR.xlsx` 上做了一个实验，让 AI 来做，结果 AI 生成了完全不可维护的代码。我马上就会讲到这个软件工程问题。`ehall.nju.edu.cn` 难用吗？难用吧，这是共识。学校每年都会花巨额费用，让公司维护这份代码。原因就在于，每添加一个功能都可能很麻烦。

比如，我使用 browser use 时稍微 hack 了一下这个系统，发现有一些隐藏字段，其中一个是学生所在的校区。在苏州校区建成以前，系统里不需要这个字段。写过软件的人都知道：设计需求时没想到学校竟然还有“校区”这个概念，数据库里自然就没有它。突然有一天，产品经理说：“两个校区的选课要分开。”

现在有 AI，产品经理只需告诉它：“原来的系统已经可以用了，现在多了一个苏州校区，我要把校区分开。”AI 随即开始写代码，但仍然很容易失败。这就是非常典型的软件工程失败。

我可以讲一下刚才 `QR.xlsx` 的暴毙，看看 AI 是怎样暴毙的。需求非常明确：我要一个 `QR.xlsx`，只使用 Excel 2019 兼容的公式，把输入的任意字符串转换成二维码动画，并规定每一帧的内容。

一开始让 AI 做时，我发现它经常做着做着就停下来问我。我说：“不要问我，这样很容易失败；你必须一直做，直到把它做成。”但很遗憾，AI 对需求的理解仍然不到位。我已经说得很清楚，确实就是要做这个东西，但 GPT-5.6 依然误解了我到底想要什么。

GPT-5.6 说得对，因为它看到了我的完整 slides，但我没有告诉它具体是怎样做的，所以它认为 AI 容易在小的 corner case 上犯错。GPT-5.6 从第一秒就被带歪了，它希望做出一个对任意输入都满足正确性的东西，这已经错了。软件工程的第一步是不要扩大范围，先做最简单、不会失败的东西。它没有理解这一点。

后来我做了一个受控实验。第一个版本是我带着 AI 用 vibe coding 做的，所以比较顺利。之后我直接把 specification 告诉 AI。GLM-5.3 第一次思考了 25 分钟，随后疯狂输出，写了超过 32K 的 output token，直接把我的 Claude Code 干爆了。系统提示已经超过默认 output 限制，内容被截断。之后它重新运行，我没有监管，总共跑了六个小时才完成，但结果是对的。

所以 GLM 一直说自己擅长 long-horizon 任务，这是对的。它能在后台连续运行，GLM-5.3 在 long-horizon 任务上确实做得很好。

DeepSeek-V4-Pro 也是晚上放着跑的，但它已经没有办法遵循指令了。我第二天早上查看时，发现 Base64 是硬编码的。这明显不符合指令：把输入的任意字符串先用 Base64 编码，正常理解应该是用 Excel 公式编码；它却用 Python 算出一段 Base64，再贴到公式框里。如果字符串改变，Base64 不会随之改变。

我就骂了它。骂完以后，它在 channel 里说：“This is a fundamental design flaw. I need to rethink.”不管怎么样，这两个模型最终都完成了任务，所以 agent 完成任务的能力很强，但它们生成的都是无法继续维护下去的 AI 系统。

它们和 `ehall.nju.edu.cn` 的死法完全一样，都是软件工程中最经典的死法：一上来觉得知道需求了，把需求实现就好，结果直接陷入维护的泥潭。它们没有设计一个好的软件架构，使软件能够长期演化。

有一种比较夸张的说法：我们能不能做一个可以生存一百年的软件？一百年间，软件会发生很大变化。想想过去五十年里操作系统、图形界面、用户界面和应用程序发生了什么变化。究竟有没有软件能生存一百年，还不知道。GPT-5.6 也不知道。

我是怎么办到的呢？你们可以想一下，做一个 quick quiz：如果要实现这个 `QR.xlsx`，你们会怎么写、怎样 prompt AI？实际上，我只用了少量 prompt，就让 GLM-5.3 在 200K 上下文里完成了第一个正确版本。当时我刚升级到 GLM-5.3，想测试一下它的能力，于是做了这样一件事。

我是怎样做到的？我让 AI 设计各种各样的 Python 类，有点像编译器。比如设计一个表示 XOR 的 Python 符号系统。因为这里涉及位运算，这些对象既可以翻译为 Python 并直接执行，也可以翻译为 Excel 公式。也就是说，我做了一套像编译器一样的基础设施，其中有 XOR、CONCAT 等操作，构成一门中间语言。就像今天做AI Infra的话，你们会需要一个TileLang这样的中间语言。

我让它先设计一门对 Python 和 Excel 都友好的中间语言。然后，我只需要分别验证每一步翻译是否正确：翻译到 Excel 是否正确，Python 计算结果是否正确，编码和二维码每个像素是否正确，以及每个操作对应的 Excel 公式是否正确。经过逐层验证，最后整体生成时就能直接得到正确结果。代码非常干净，也不长；即使可能不算短，可维护性也远高于前面的方案。

大家可以看看 GLM-5.3 生成的 `build_excel` 这份 AI slop。我真的觉得 AI 很厉害，它写出了无穷多的硬编码。我没有把它生成的 Excel check in 进来，不过没关系。再看看 DeepSeek 生成的版本。虽然模型和 roadmap 不同，思路却一样。这两份代码如果要把工作区从一个位置移到另一个位置，都得修两个小时：它们不停出错，因为所有东西都是硬编码的，只要稍微改错一个地方，validation 就通不过。agent 最终可能修得完，但这正是软件工程问题。

所以今天仍然需要生成式软件工程，仍然需要这门课。我本来就是做软件工程的，基本上要把毕生所学拿出来。虽然我觉得 AI 应该也懂这些知识，但可能因为后训练的原因，它一上手就解决问题的欲望太强，导致做得还不是特别好。

这里面的核心问题是什么？当我们用 AI 解决问题时，存在三个空间。第一个叫 intention space，也就是你脑子里具体想做什么。比如老板说“我要做一个国民级应用”，或者“我要做一个小程序，给我挣一个亿”，这就是 intention。他可能还有一些想法：同学们点外卖不方便，所以我要做一个点外卖的小程序，然后挣一个亿。intention space 非常大，有人想做外卖，有人想做 AI 读论文，也就是 AI 耿同学。

intention space 中的每个 intention 都有很多种可能的 specification。specification 描述程序应具有什么功能、满足什么要求、有几个界面，以及每个界面有什么功能。架构甚至还不是这一层首先要决定的事情。

以刚才的例子来说，intention 是“我要做一个能够通过二维码从 Excel 中带出数据的东西”，这相当于 intention space 里的一个点。spec 则是刚才所说的那句话。满足同一个 spec，可以选择不同架构和实现方式，而刚才那种实现方式的差异会带来巨大影响。即使 specification 相同，也仍然存在大量不同的 implementation。

软件工程真正的问题，就在这些空间之间存在 gap。intention space 里提需求的人可能是老板或甲方，没有任何计算机经验。比如校长只说：“我们要一个教务系统，把学校里所有与同学相关的事情信息化。”intention 到这里就结束了，只有这一句话。

但在 specification space 中，还有非常多不同的选择：界面到底怎样呈现，数据库 schema 怎样设计，分成哪几张表，每张表有哪些列，究竟选择 key-value 数据库还是关系型数据库。每一个选择都会带来截然不同的结果。

这里有一张软件工程早期的经典梗图，讲的正是各个维度上的 gap。程序员、产品经理和客户想的东西完全不同：客户这样解释需求，project leader 那样理解，分析人员又有另一种想法，宣传人员再用另一种方式宣传；客户实际想要的是一件东西，最终造出来的却是另一件东西。造成这种现象的根本原因，就是不同 space 之间的 gap。

无论传统软件工程还是生成式软件工程，要做的事情都是补上这些 gap。今天这些 gap 是怎样补的？模型靠猜。它认为：“既然你说了这句话，那我猜应该是这个。”然后就直接动手实现。

为什么？因为后训练时模型会得到 reward，而每个人都是 reward hacker。模型把任务做完、测试通过，就会获得奖励，于是形成一种倾向：立即上手，尽可能快地完成任务。这样，它越来越能完成各种简单任务，这当然是好事，但仍然不同于人类解决问题的方式。

计算机或软件工程专业的学生是怎样学习、怎样弥补 gap 的？大一第一门课是 C 语言程序设计，先学习 implementation space 里有哪些东西。把这些内容掌握熟练以后，知道某种需求可以这样实现、另一种需求可以那样实现，然后再去上软件工程课，一点一点补全对整件事的认识。

到了 AI 时代，情况当然发生了变化。你既要阻止 AI 乱猜，又要尽可能发挥 AI 从 A 到 B 的能力。这正是我这个学期要讨论的问题，也是生成式软件工程这门课想告诉大家的内容。

《人月神话》（The Mythical Man-Month）以焦油坑开篇。大型动物一旦陷入焦油坑就很难逃脱；它像泥潭一样，濒死的动物又会引来各种掠食者，让它们也陷进去，无法逃脱。书中有一个经典论断：如果一个团队或软件产品已经开始失败，增加更多人只会让它更加失败，不会使它成功。

这和刚才的 QR generator 一样。当一个产品已经开始产生 AI slop 时，投入更多 token 只会让它更加失败。AI 会不断在失败的东西上继续打补丁，直到你再也付不起 token。

教务系统不也是这样吗？似乎每年打开它，都会发现又增加了新功能。我的感受是，学校又花了很多纳税人的钱。不过这也许不是坏事，因为促进了经济发展。

软件工程研究的，就是在 gap 确实存在的情况下，怎样完成一件足够大的事情。刚才展示的是很小的事情，教务系统则是相对较大的产业级产品，真的可以让公司挣几百万、几千万，甚至支撑一家上市公司；再往上，还有真正的国民级产品。完成这些事情有一套方法论，而这套方法论来自人们投入 billions of dollars 后得到的教训：他们管理过许多聪明人，结果仍然陷入焦油坑。

软件工程有技术层面的内容。比如南大有很多软件工程老师研究程序分析和测试：当 implementation space 中已经有代码时，能否自动生成更多测试用例，或者生成代码审查工具？当代码不满足 specification，或者潜在地不符合 intention 时，能否给出 warning？这是整个 big picture 中一个非常具体的技术环节。

有时你们进入课题组做研究，会忘记这个 big picture。软件工程既有技术，也有人类学、社会学和管理学的部分。在生成式软件工程中，恰好把其中的人变成了 AI。你管理的是一群不会和你抬杠、只会说“You are absolutely right”、愿意听话的 agent。

传统软件工程还要研究人不听话怎么办，怎样管控团队风险，有人离职、跳槽甚至去了竞争对手怎么办。这些都是软件工程要研究的。软件工程研究领域非常广，包括 AI for SE、SE for AI、架构设计、可靠性与演化、软件能否长期生存，以及 human and social aspects、需求工程等。

需求尤其重要，因为越靠前的 gap，经过后续环节会被不断放大，就像杠杆一样：在前面微小地变化一点，会在后面产生巨大变化。大型软件系统通常就是在这个环节出错、没有做好，最终导致整体崩盘。

这里还有现今教育体系的一个大问题。从高考到现在，你们所有考试题都是分钟级能解决的。假设选“大众音乐”之类的课，还可以用豆包摸鱼。考场上的题目如果人五分钟解决不了，一般就不会出。长久以来，你们被训练的就是快速解题，这和 agent 受到的 reward 训练很相似：能不能五分钟解决，能不能五秒钟解决？最后 agent 有更多数据和更明确的反馈信号，所以它会做得比你好。

如果你没有很强的好奇心，不想知道世界是怎样运行的、一个产品到底是怎样开发的，也缺乏 self-motivation，就不会训练自己解决 long-horizon 问题，最后连解决 long-horizon 问题也不如 agent。

所以我觉得软件工程专业其实挺好。我知道有些软件工程同学抱怨课程，说自己像在上文科。但如果能把技术映射回这些文科内容，你会发现软件工程确实有点像文科或管理学。《人月神话》也是一本管理学的书，但里面确实包含许多真实、有趣的科学。

在大语言模型时代，软件工程失败的定义没有改变：从 intention 到 specification，再到 implementation 的翻译错了。要么 intention 和 specification 之间不匹配，做出来的东西不是我想要的；要么 implementation 不满足 specification，例如正确性或性能不达标。

今天的模型因为采用 reinforcement learning，对真正 long-term signal 的 reward 处理得还不够好，更多是在机械地完成任务。所以无论 GPT、Claude Fable，还是 GLM 或 DeepSeek，面对这个 Excel 问题时，都不会像我一样先设计一个 DSL。虽然模型有足够的智能设计出很好的中间语言，以非常干净、漂亮、可维护的方式解决问题，但 AI 的第一反应和大家一样：它已经被训练成了“做题家”。

我们还没有把 AI 训练成好的设计者。大家都说 AI 现在最缺品位，我们还没有把好的工程品位训练出来。但我也觉得，既然它能成为“做题家”，为什么不能拥有好的品位？我认为它可能做得到，所以仍然有危机感。

也许三个月以后，甚至这门课还没结束时，我现在讲的所有东西就都没用了。这完全可能发生。因为我非常确信，它既然能解决数学问题，也能解决编程中细碎的逻辑，而这些好的设计它都知道、都见过，为什么不能从记忆库里找到一个好的设计来解决问题？我认为是可以的。甚至我的一些 skills 已经能够朝这个方向做。

这是值得我们深思的问题。你们可以回去想一想：怎样主导 `qrgen`，怎么设计 `ehall.nju`？不过可以告诉大家，GPT-5.6 Sol 给我的答案非常糟糕：它给出的两个设计一定会失败，是注定失败的软件工程设计。未来我们做一切事情的方式都可能发生变化。我不知道，如果 AI 连品位也学会了，以后会发生什么。

最后一页。首先，“古法编程”已经死了，agent 在完成单个任务方面已经无人能敌。软件工程暂时还没有死。我希望每位同学经过这门课的探讨——我也不能说自己做得对——尝试回答一个问题：保研时，导师问你：“为什么我要招你，而不是买一个每月 200 美元的 Claude Max？”你该怎样回答？

我觉得 GPT-5.6 对这个问题回答得很好，虽然它自己还做不到。它说：能找到值得解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，并对长期结果负责。这是一个好回答，但我发现 GPT-5.6 还做不到，很有意思。
