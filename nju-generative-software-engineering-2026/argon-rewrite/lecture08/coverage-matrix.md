| 来源 | 要点 | 去处 |
|---|---|---|
| 官方课件 slide-002 及官方讲义《总得从一个能运行的原型开始》 | 用选课系统“两人同时抢最后一个名额”和 1901 年莱特兄弟滑翔机升力仅达预测值 1/3 进而自建风洞重测数据的例子，说明纸面符合 Spec 不代表隐含假设成立，“Let it fail”是为了让隐含假设变成可观察的事实。 | 第一章 从意图到可运行的原型：用“Let it fail”暴露隐含假设 |
| 官方课件 slide-003 及官方讲义《同一个提示词，不断变化的世界》 | 提出“给足够聪明的模型一个 Bash 工具就能造芯片、证明黎曼猜想”的思想实验（类比早期 UNIX 大师在纯 Shell 中完成工作），借此反衬现实模型尚未万能、尤其难以仅凭一句提示词学会工程品味。 | 第二章 Agent Loop 与状态机视角：在变化的工作区中推进长程任务 |
| 课堂口述字幕（关于博士生研究倾向与双模型互评）及《实验 (2)：Deeper Research - 2.1 算力换智力》 | 将 Agent 与博士生类比：收到任务后容易沿着第一个想到的方案一路走到黑（DFS），而优秀问题求解者会结合宽度优先搜索（BFS）在设计空间浅层广泛采样；实践中可让 GPT 与 Claude 互相挑刺评审，利用不同模型的偏见分叉搜索路径。 | 第二章 Agent Loop 与状态机视角：在变化的工作区中推进长程任务 |
| 课堂口述字幕（关于 150 行最小 Bash Agent 演示与网络环境差异） | 现场演示约 150 行 Python 编写的最小 ReAct Agent（含 `run_bash` 工具调用协议），指出玩具代码硬编码了命令 Timeout，而教育网与境外网络执行 `git clone` 的速度差异巨大，固定超时会导致误杀，生动展示了最小原型到真实产品的架构差距；同时提醒防范终端未锁屏导致 API Key 泄露。 | 第二章 Agent Loop 与状态机视角：在变化的工作区中推进长程任务 |
| 课堂口述字幕（关于个人名片生成对比与模型升级背靠背测试）及《实验 (2)：Deeper Research - 2.3 评估效果》 | 展示同一模型制作个人名片的两种结果：One-shot 直出版本有华丽的毛玻璃与终端动效，但邮箱和院系标签均错误；Ralph Loop 迭代版本外观朴素，却准确核对了副教授职称、邮箱与 GitHub 链接。同时警告旧版好用的 Prompt 在新模型上可能失效甚至倒退，必须做固定输入的背靠背对比评估。 | 第二章 Agent Loop 与状态机视角：在变化的工作区中推进长程任务 |
| 课堂口述字幕（关于导师批评烂代码与模型顺从傾向的对比） | 对比人类导师与大模型：导师可以对拿到零分架构代码的学生直接叫停并要求推倒重来；而大模型面对上下文中已有的劣质代码（Slop）具有强烈的顺从倾向，总是试图在烂代码基础上修补维持，从而把项目拖入泥潭。 | 第二章 Agent Loop 与状态机视角：在变化的工作区中推进长程任务 |
| 官方课件 slide-007、官方讲义《每次迁移都检查：重新发现 CI/CD》及课堂口述字幕 | 引用计算机系统公理“机器永远是对的，未测试的代码永远是错的”，结合学生做 OJ 过样例就交、改一行代码觉得不会出事、实习生推 PR 挂掉生产系统等投机行为，论证“开发者是不可信的”这一 CI 第一性原理。 | 第三章 每次状态迁移都检查：从“开发者不可信”重新发现 CI/CD |
