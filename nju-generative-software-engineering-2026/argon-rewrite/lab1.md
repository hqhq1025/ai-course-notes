# 实验 (1)：会成长的个人助手

本课程的实验是建议性质的实验，不记分。你可以直接将实验要求交给模型，配合一个 Grill Me 之类的技能，让它追问你的需求，再一起完成实现。怎样把“我想要”变成可以验收的软件，也是实验的一部分。

## 1. 背景

课堂上，我们已经展示了通过浏览器自动完成日常信息化流程的案例。有了 Agent，我们可以期待更多：让个人资料、邮件、办事大厅和手机连接起来，把一次成功的尝试变成随时可用的能力，并且在被你纠正之后，下次能把事情做对。

## 2. 实验要求

🗒️**实验要求：实现会成长的个人助手**

实现一个持续为你工作的个人助手，具备以下五项基础能力。可以基于现有 Agent 配置工具、脚本和技能；语言、模型和交互形式不限。

1. **个人数据库。** 能索引、检索你的资料，并随资料变化更新索引，回答时能定位到原文。格式不限，推荐 Markdown + 目录结构：你可以直接阅读、修改文件，也更容易观察 Agent 读了什么、写了什么，以及如何组织记忆。
2. **持续关联 smail 邮箱。** 能持续获取新邮件、关联历史往来，结合个人资料拟好回复草稿。你可以编辑草稿，再直接发送；发送的应当是你确认的最终版本。重复检查邮箱不应重复处理或发送同一封邮件。
3. **办理 ehall 事务。** 能在 `ehall.nju.edu.cn` 中查询信息，并完成至少一种事务的材料准备和表单填写。行为要保守：提交前展示关键字段及后果，由你明确确认；退课、撤销申请等操作尤其不能自行决定——万一 Agent 把你的课都退了，你就完蛋了。
4. **手机端联动。** 能方便地从手机发起任务、查看进度、编辑草稿和确认操作。可以做 App、网页，也可以借助手机已有功能。例如，在 Mac 上用 AppleScript 操纵备忘录，再通过同步与手机联动。任务不能依赖桌面端某个始终开着的对话窗口。
5. **能力组合。** 上述功能应当能共享必要的上下文，完成跨工具的任务。如何组合由你决定，但至少做出一条你愿意反复使用的完整流程。

例如，收到办事通知后，助手检索个人资料，整理待补材料，在手机上向你追问，准备 ehall 表单和邮件草稿；你核对后分别提交、发送，结果再归档到个人数据库。也可以设计完全不同的流程：**这是一个发散的任务，组合方式本身就是你的设计。**

将成功流程和你的纠正保存成可阅读、可修改的脚本、技能或记忆，用 Git 管理实现和规则。例如，你指出“不要把报名截止时间当成活动开始时间”，助手应当能在新会话中将这条规则用于另一份通知。

## 3. 为什么要布置这个实验？

因为如果你直接把这些需求 (在明确和不明确之间) 给 AI Agents，你将大概率得到一团乱麻的 AI slop——它也许的确可以工作，但每一次修改都会消耗大量的 tokens，Agents 会在泥潭中反复阅读代码、试错，像极了《人月神话》中的软件焦油坑，从而迫使你思考应该如何重新组织项目——但这是好事，因为 AI 重构的能力极强，一旦你找到一个更好的架构，瞬间就会改进。

请留存好你的项目，它可能会是你成为 AI-native 新人类的起点——之后我们也会持续地改进它。
