# Argon 写作流程

新课程讲义、视频笔记、访谈和文章笔记，以及已有讲义的实质重写，默认由 Argon 撰写正文并完成整篇润色。历史文件保留实际的生成记录。

## 分工

| 环节 | 执行者 | 产物 |
|---|---|---|
| 获取和核对资料 | Codex | 官方材料、完整字幕、时间戳、来源清单 |
| 确定教学结构 | Codex，必要时请 Argon 协助 | 覆盖矩阵、讲者要点、写作蓝图 |
| 撰写正文 | Argon | 章节初稿、导读、小结、总结与延伸 |
| 全文润色 | Argon | 衔接自然、术语一致的完整正文或精确修改 |
| 内容复核与配图 | Codex | 事实修正、机制图、术语表、图文对应检查 |
| 排版和交付 | Codex | LaTeX、PDF、网页、检查记录 |

## 从来源到正文

1. 先取得完整口述和可用的官方资料。字幕保留时间戳，ASR 原稿与校订稿分开保存。
2. 建立讲者要点表，记录问题、动机、例子、尝试、纠正、分歧和结论。覆盖矩阵为这些内容安排正文去处。
3. 按教学问题确定章节，将实际来源文本放进 Argon 的请求，包含相关字幕和口述解释。
4. 长讲义按完整论证分章写作。每次请求带整篇蓝图、对应来源及相邻章节上下文。能容纳完整转录时，直接提供完整转录；分段时明确段落范围及边界衔接。
5. 将合并后的全文交给 Argon 编辑，统一术语、解释层次和前后衔接。正文以讲解为主，比较用表格，并列观点用分点，步骤用编号，关键短语适度强调。
6. 复核原文与成稿。实质性改写交回 Argon；确定的事实、拼写、公式和排版问题可直接修正。最后执行项目的编译、覆盖检查和视觉验收。

有课件时继续覆盖全部教学页，并把图片放到对应论证中。不要把逐页覆盖变成固定的“每页若干段”，也不要把口述一律压进图后补充。没有课件的访谈用问题和讨论过程组织章节。

来源中的条件和观点归属写在相关解释里。删除反复出现的泛化免责声明，保留会改变读者理解的具体条件。不要为了页数增加套话、重复图或无关公式。

## 调用

本仓库的共享入口是 `tools/scripts/argon_write.py`。当前主机已验证的兼容地址是 `http://127.0.0.1:8536/v1/chat/completions`；其他主机通过 `ARGON_ENDPOINT` 指定已验证的地址。脚本不读取或修改客户端凭据。

在已安装 `requests` 的 Python 环境中运行。离线测试另需 `pytest`，命令为 `python3 -m pytest -q tests/test_argon_write.py`。

```bash
python3 tools/scripts/argon_write.py \
  --prompt lecture/generation/chapter-01-input.txt \
  --output-prefix lecture/generation/chapter-01
```

提示词应包含来源正文，并给出期望的 JSON 输出结构。

每次请求使用新的输出前缀。脚本保存提示词、原始输出和简短回执，确认 Argon 完整返回且 JSON 可解析后，写出结果。失败时保留错误信息，便于续写。

日常写作检查来源内容、成稿和渲染结果即可，不生成文件哈希、来源快照或专门的溯源核验报告。来源清单保留标题、链接及页码或时间戳，方便读者回看。含私人资料的请求日志不随讲义发布。

## 断流与续写

保留失败回执，先判断是连接错误、输出截断还是 JSON 格式问题。只重试受影响的章节；长输出断流时缩小单次写作范围，再对合并全文润色。成功章节和原始来源继续复用。

遇到 `quota exceeded` 或上游 HTTP 429 时，先查看代理是否已尝试现有账号。现有通道均无额度时，暂停新的正文请求，保留蓝图、来源和已完成章节，待额度恢复后用新输出前缀续写。缩小章节或反复重试不能解决额度耗尽。

不要自动切换其他模型。路由暂时不可用时，继续资料、图表和检查工作，并说明具体故障及正文完成情况。后续恢复调用后，用同一蓝图和保存的章节接续。
