\section{Agent Externalization：把能力沉淀到参数之外}

刘卫文的报告讨论从 model scaling 走向 agent evolution 的路线：很多能力不必全部压入基础模型参数，而可以外部化为 memory、tool、skill、workflow 和可持续修改的 harness。Externalization 降低更新成本，也让能力更容易审计与组合。

\subsection{从 Model Scaling 到 Agent Evolution}

基础模型提供通用先验，但部署后的改进往往来自外部组件：检索记忆补充新事实，工具提供可执行能力，技能库保存成功流程，harness 决定调用顺序。系统的有效 policy 因而是模型与外部状态的联合函数。

\sourcefigure{0.93}{lecture07/slides-images/slide-005-00390s.jpg}{Model--Harness co-evolution 的研究路线}{00:06:30--00:09:00}

\begin{importantbox}{Externalization 的判断标准}
需要频繁更新、可解释、可删除或可组合的知识更适合外部化；稳定而广泛复用的模式适合进入参数。错误的边界会导致要么上下文过载，要么每次小变化都必须重新训练大模型。
\end{importantbox}

\subsection{BALTO：从反思文本到可复用行为}

BALTO 类方法让 Agent 从失败轨迹中产生 reflection，再把反思用于下一轮行动。关键不是生成“下次更仔细”的空话，而是抽取可触发、可执行、可验证的规则，并评估它是否跨任务迁移。

\begin{warningbox}{Memory pollution}
若每次失败都写入长期记忆，错误归因、偶然经验和互相冲突的规则会迅速污染 context。记忆系统需要置信度、作用域、版本、去重和淘汰机制，并通过真实执行验证写入内容。
\end{warningbox}

\subsection{LongTool：让工具能力可增长}

工具学习不仅是选择已有 API，还包括理解长工具文档、组合多个工具并把成功调用沉淀为 reusable skill。LongTool 关注长上下文工具环境下的学习与泛化，说明外部工具生态本身可以成为 Agent 进化的能力库。

\subsection{SKiMAS 与 MIMSkill：Harness 和多模态技能也能学习}

SKiMAS 把 harness 视为可修改对象，让系统从交互中更新模块编排；MIMSkill 则把文本技能迁移到多模态任务。两者共同说明，skill 可以成为连接抽象策略与具体环境的中间表示。

\begin{knowledgebox}{Skill 的工程定义}
一个可复用 skill 至少应包含触发条件、所需输入、动作序列、失败恢复和完成判据。只有自然语言总结而没有执行接口的“技能”，很难稳定进入自动规划。
\end{knowledgebox}

\subsection{ProAct：从被动响应到主动交互}

当 Agent 能维护长期目标和环境状态后，它不必等待用户每次明确提问，而可以在合适时机主动提醒、收集信息或执行准备动作。ProAct 研究 proactive interaction，同时也暴露新的治理问题：主动行为必须控制打扰、权限和不可逆风险。

\subsection{本章小结}

能力外部化使 Agent 可以用更低成本持续学习：memory 保存经验，tool 扩展行动，skill 固化流程，harness 组织组件，proactive policy 决定何时主动行动。真正的 self-evolving system 应同时研究 model evolution 与 harness evolution，并给外部状态配置治理和回滚机制。
