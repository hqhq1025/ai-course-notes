\section{Agent-World：让训练环境与策略协同进化}

董冠霆的 Agent-World 把 self-evolving Agent 的瓶颈定位在环境侧：Agentic RL 需要大量可执行、可验证且难度可控的任务，但人工构造环境和标注奖励无法跟上策略增长。解决思路不是只扩充数据集，而是建立能持续发现环境、合成任务、验证结果并诊断能力缺口的 arena。

\sourcefigure{0.94}{lecture04/slides-images/slide-002-00030s.jpg}{Agent-World 的目标：策略智能与环境供给协同进化}{00:00:30--00:01:00}

\subsection{环境不足为何成为 Agentic RL 的主要约束}

语言模型预训练可以从静态语料获得海量 token，Agent 训练却要求每个样本都具有状态、工具、动作和可执行反馈。真实服务 API 可能不稳定、昂贵或涉及隐私；手工 sandbox 又覆盖有限，最终导致策略反复在少数 benchmark 上优化。

\sourcefigure{0.94}{lecture04/slides-images/slide-003-00060s.jpg}{Agentic Environment--Task Discovery 从主题空间寻找可执行环境}{00:01:00--00:04:15}

\begin{importantbox}{环境是训练分布的一部分}
Agent 的能力上限不仅由模型和算法决定，也由它能接触到的工具生态、数据库模式、任务难度和验证器决定。环境单一时，继续增加 rollout 只会更充分地过拟合有限交互模式。
\end{importantbox}

\subsection{第一阶段：Environment--Task Discovery}

Agent-World 先从大规模真实主题出发，寻找数据库、API 或可执行工具集合，再把它们标准化为统一交互接口。随后系统分析 schema 与工具能力，提出需要多步查询、组合或推理的任务。

\sourcefigure{0.94}{lecture04/slides-images/slide-004-00255s.jpg}{从环境主题、工具能力到候选任务的发现流程}{00:04:15--00:07:45}

\begin{knowledgebox}{Task discovery 不等于随便生成问题}
高价值任务必须依赖环境中的真实状态，答案不能仅靠语言先验猜出；任务还应要求多个工具步骤，并覆盖不同错误模式。否则生成器会生产看似丰富、实则不需要交互的伪 Agent 任务。
\end{knowledgebox}

\subsection{第二阶段：Verifiable Task Synthesis}

合成任务最大的风险是无法可靠判分。Agent-World 通过环境约束、程序执行、数据库查询或规则检查构造 verifier，使 reward 尽量来自外部状态而非另一个语言模型的主观判断。

\sourcefigure{0.94}{lecture04/slides-images/slide-005-00465s.jpg}{可验证任务合成：同时生成任务、执行条件与验证逻辑}{00:07:45--00:09:15}

若任务 $q$ 的目标状态为 $g_q$，Agent 轨迹为 $\tau$，验证器可写成

$$
r(\tau,q)=\mathbb{I}\!\left[V\!\left(s_{\mathrm{final}}(\tau),g_q\right)=1\right],
$$

其中 $V$ 是确定性或受控随机验证程序。对于长轨迹，还可加入格式、工具约束和中间状态检查，避免 Agent 通过奖励漏洞绕过真正任务。

\begin{warningbox}{可验证不等于没有 reward hacking}
如果 verifier 只检查最终字符串，Agent 可能伪造答案；如果只检查数据库状态，又可能通过未授权副作用完成目标。验证器必须同时覆盖结果、过程约束与安全边界，并对生成任务做独立审计。
\end{warningbox}

\subsection{第三阶段：Continuous Self-Evolving Agent Training}

环境与任务准备好后，系统使用多环境 Agentic RL 训练策略，再把评测中暴露的弱点送回 arena。Arena 不是固定 leaderboard，而是一个诊断器：它识别模型在哪类工具组合、长程依赖或错误恢复上失败，并定向生成下一轮任务。

\sourcefigure{0.94}{lecture04/slides-images/slide-008-00705s.jpg}{Agent-World 的闭环：环境发现、任务合成、训练与诊断}{00:11:45--00:12:30}

\sourcefigure{0.94}{lecture04/slides-images/slide-010-00840s.jpg}{多环境 Agentic RL 工作流与自进化 arena}{00:14:00--00:15:00}

\begin{importantbox}{协同进化的含义}
策略变强后，旧任务失去训练价值；环境生成器必须提高组合复杂度或引入新工具。反过来，新环境暴露的失败又决定策略下一轮训练重点。两侧共同变化，才称得上 agent--world co-evolution。
\end{importantbox}

\subsection{实验结果与正确解读}

报告在多项 Agent benchmark 上比较基础模型、仅增加环境数据、以及完整 Agent-World 闭环。总体趋势是，跨环境训练比单一 benchmark 训练具有更好的平均迁移，定向生成的任务还能改善特定弱项。

\begin{warningbox}{Benchmark 增长不等于现实世界已解决}
合成环境仍可能比真实系统更整洁，工具错误、权限变化、延迟和非确定性都较弱。实验支持“可扩展环境合成有效”，但不能直接推出 Agent 已能在开放互联网或企业系统中长期自治。
\end{warningbox}

\subsection{本章小结}

Agent-World 将训练数据问题升级为环境工程问题。系统先发现可执行环境，再合成带 verifier 的任务，通过多环境 RL 训练策略，并用 arena 诊断弱点、生成下一轮课程。它与前两章形成自然连接：causal world model 帮助理解环境，rollout infrastructure 负责规模化交互，Agent-World 则持续提供值得交互的新世界。
