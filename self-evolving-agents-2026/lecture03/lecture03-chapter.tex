\section{从 Foresight Failure 到有目标的自进化}

钱成的报告研究一个常被忽略的 Agent 能力：\textbf{foresight}，即在行动前预见环境演化、工具后果和长期约束。Agent 可以拥有工具，也可以接入 world model，但这不代表它会在正确时机调用、会相信模型，或能把预测转化为更好的决策。

\sourcefigure{0.92}{lecture03/slides-images/slide-004-00105s.jpg}{Agent 是能够感知、推理、行动并接收反馈的交互系统}{00:01:45--00:03:45}

\subsection{Foresight 是比“会调用工具”更高一层的能力}

在复杂任务中，Agent 需要先估计动作可能引发的后续状态，再选择当前步骤。世界模型、搜索和模拟器都只是提供预测的工具；真正的 foresight 还包括识别何时预测值得付出成本、如何处理预测不确定性，以及何时停止继续想象。

\sourcefigure{0.92}{lecture03/slides-images/slide-005-00225s.jpg}{Agent 的行动空间需要从反应式工具调用扩展到前瞻式决策}{00:03:45--00:05:15}

\sourcefigure{0.92}{lecture03/slides-images/slide-006-00315s.jpg}{World model 作为工具：预测动作之后的环境变化}{00:05:15--00:07:15}

\begin{importantbox}{能力缺口不一定在模型精度}
实验发现，即使提供较强 world model，Agent 也可能很少调用它；即使调用，也可能在输出与原有判断冲突时选择忽略。系统失败因此不能只归因于“预测器不准”，还要检查调用策略、信任校准和决策整合。
\end{importantbox}

\subsection{实验：更好的 world model 为何没有自动带来更强 Agent}

报告在多个交互任务中替换不同能力的 world model，并比较 Agent 最终表现。理想情况下，预测器更强应单调提高成功率；实际结果却显示收益有限，说明模型能力与 Agent 使用模型的能力之间存在明显接口鸿沟。

\sourcefigure{0.93}{lecture03/slides-images/slide-007-00435s.jpg}{实验设置：不同任务、world model 与 Agent 组合}{00:07:15--00:07:45}

\sourcefigure{0.93}{lecture03/slides-images/slide-009-00540s.jpg}{Agent 对 world model 的调用存在显著 reluctance}{00:09:00--00:09:15}

\sourcefigure{0.93}{lecture03/slides-images/slide-011-00660s.jpg}{Foresight failure 的典型模式与性能损失}{00:11:00--00:13:15}

报告归纳的失败可理解为三类。第一，\textbf{不调用}：Agent 直接依据语言先验行动。第二，\textbf{调用但不整合}：预测只成为附加文本，没有改变计划。第三，\textbf{错误信任}：Agent 无条件接受预测，反而被不可靠 world model 带偏。

\begin{warningbox}{World model 不是 oracle}
部署系统必须同时估计预测误差与使用价值。若模拟器在分布外状态上不可靠，强制每一步都调用会增加延迟并传播错误；若从不调用，又浪费了可用于规避高成本失败的信息。正确目标是学习 calibrated invocation policy。
\end{warningbox}

\subsection{Foresight Governor：把“是否思考未来”显式化}

报告提出治理式视角：在执行 Agent 外再增加一个模块，决定何时请求预测、选择哪个 world model、如何把结果写回决策上下文。这个 governor 不应只靠 prompt 临时提醒，而要接受显式训练，让“使用 foresight”本身成为可优化行为。

\sourcefigure{0.93}{lecture03/slides-images/slide-012-00795s.jpg}{Foresight Governor 将预测调用与主策略分离}{00:13:15--00:14:45}

\sourcefigure{0.93}{lecture03/slides-images/slide-013-00885s.jpg}{显式训练是获得稳定 foresight 的必要条件}{00:14:45--00:16:15}

\begin{knowledgebox}{为什么 prompt 提醒不够}
“行动前请认真预测”只改变当前上下文，不能保证模型在新任务、长轨迹或冲突证据下保持同样策略。显式训练通过大量成功与失败轨迹塑造调用倾向，并让模型学会比较预测收益与成本。
\end{knowledgebox}

\subsection{Test-Time Training：把一次任务变成局部学习过程}

报告进一步把 self-improvement 放到测试时：Agent 在处理当前任务族时，先从失败轨迹产生 self-awareness 或可复用经验，再把这些经验用于后续 episode。更新可以发生在 memory 层，也可以通过小规模训练进入参数层。

\sourcefigure{0.93}{lecture03/slides-images/slide-014-00975s.jpg}{Test-time training 的两条路径：记忆增强与参数更新}{00:16:15--00:18:00}

\sourcefigure{0.93}{lecture03/slides-images/slide-015-01080s.jpg}{两种 self-improvement setting：同任务重复与任务分布迁移}{00:18:00--00:19:15}

\begin{importantbox}{Self-awareness 与 self-improvement 要分开}
Self-awareness 是识别“我为什么失败、缺少什么能力”；self-improvement 是据此改变后续行为。只生成漂亮的反思文本不代表能力提升，必须验证它是否改变了调用、规划或训练结果。
\end{importantbox}

\subsection{Generator--Solver 与自动 curriculum}

为了不让 Agent 只重复已有任务，报告引入 generator--solver 结构。Generator 根据当前 solver 的能力边界产生新问题；solver 尝试解决并返回结果；课程设计器再依据成功率、难度和新颖性调整任务分布。

\sourcefigure{0.93}{lecture03/slides-images/slide-018-01245s.jpg}{Generator--Solver 通过竞争与反馈形成自适应课程}{00:20:45--00:21:45}

\sourcefigure{0.93}{lecture03/slides-images/slide-020-01350s.jpg}{Curriculum reward 同时约束可解性、难度与多样性}{00:22:30--00:23:45}

设生成任务为 $q$，solver 成功概率为 $p_\theta(q)$。一个实用 curriculum 不应只最大化失败率，而应偏好能力边界附近的问题，例如

$$
r(q)=\underbrace{p_\theta(q)(1-p_\theta(q))}_{\text{边界难度}}
+\lambda\,\mathrm{novelty}(q)-\mu\,\mathrm{invalid}(q).
$$

过易任务没有训练增量，过难任务又无法提供可学习信号；$p(1-p)$ 在成功概率接近 $0.5$ 时最大，表达“略高于当前能力”的课程直觉。

\sourcefigure{0.93}{lecture03/slides-images/slide-026-01605s.jpg}{自生成课程带来的持续能力提升结果}{00:26:45--00:27:15}

\subsection{本章小结}

本章说明，Agent 失败常常不是“没有 world model”，而是缺少使用预测的 governor。自进化因此需要显式训练 foresight、从失败中抽取可执行经验，并通过 generator--solver 自动构造位于当前能力边界的新课程。真正的闭环是：预见失败、诊断失败、生成针对性任务、验证能力是否改变。
