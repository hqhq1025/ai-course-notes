# 全文编辑时修正

- 第二章把嘉宾“规则加验证器应有更强判断力”的解释写成了充分条件。删除“只要知识量超过就能奏效/准确批卷”的保证式结论，改成专家规则帮助弱模型检查本来不会独立解答的任务；仍取决于规则是否覆盖质量要求和验证器能否可靠执行。正文和框同步修正。
- “游戏好玩符合多巴胺曲线”仅是孙一铀提出的研究思路，不写成已经确立的普适科学指标。
- “根本不存在高管决策反馈”“无法训练奖励模型”过于绝对。解释任务不断变化、相似决策样本少、回报来得慢，使直接套用高频用户反馈的方法困难。
- 图像主观偏好的专用奖励模型是何允中讨论的可能混合方案，不写成一切生图系统的既定架构。
- 第一章保留新旧数据需求同时存在，不能把三类交付物描述成互相完全替代。供应商类型是嘉宾观察的几种能力来源，不是严格互斥的公司分类。
- 初稿第一章单段塞太多缩写和数字，拆开、精简嘉宾背景，把术语放到定义框或表格。删无必要的“显著、底层、核心壁垒、重度依赖、截然不同、彻底”等用词，让每段有具体解释。
- OCR 首次出现解释为光学字符识别；FDE 为驻场部署工程师（如用到），MCP为模型上下文协议（如用到）。同一术语统一中文名，首次给英文后自然用中文。
- 全篇用简体中文，拉丁字母与汉字间留空格，人物正式姓名以简介为准。
- 第三章把 ARC Challenge 与 ARC-AGI 混写。这里是 ARC-AGI-2 / ARC-AGI-3 的抽象推理及交互任务讨论，不是科学问答数据集 ARC-Challenge；不要将两套名称合并。
- 删掉第三章“只要刷榜就直接改善体验”的必然因果。嘉宾主张选择贴近真实工作的评测，还需要看模型在未见任务和实际工作中的表现。不要用新免责声明补洞，直接把作用条件写清。
- 第三章关于科学家用户“根本不可能足够”、长任务“几乎无法”做在线反馈，改成用户数量少、任务周期长，组织大样本反馈更困难；场景评测因而仍有作用。
- Claude Code / Codex 的比较是孙一铀当时的个人体验与解释，不确认某个具体榜单排名。缩短开头“本章将剖析”等导览句，直接接着解释。
- 第四章游戏案例出现“几千人团队”“MOBA”，转录不支持这些精确解释。统一写“一款用户体量不大的游戏，其源码在该次询价中报两三百万元人民币”，不要确定玩法类型或公司人员规模，正文/框/表全部同步。
- 第四章“无成型评测所以训练数据无从谈起”过强。改成评测与任务数据均有大量未覆盖工作，需要先梳理领域工作流。
- 第五章强化学习只有成功才学到知识的说法过度概括。限定在嘉宾讨论的以任务成功/失败为主要反馈的训练设置：如果所有尝试同为零分，就难以区分哪种行为更好；难度适配用于获得可区分的反馈。不能写成所有强化学习必须完成整题才有梯度。
- 第五章不要把嘉宾的复合奖励构想写成必须严格核算或所有RL数据的固定要求；说明可能结合正确性、资源消耗和防作弊来适应客户训练方案。评测也不都只看终点，写“节目讨论的部分结果型评测”。正文/表格/框同步。
- 轨迹定义不要求保存模型内部思考，写可记录的动作、工具调用与环境反馈。SFT可以减少初期探索困难，不保证省去后续强化学习。
- 第六章 SWE-bench 的74%到80%、剩余20%是孙一铀的印象，不能据此断言剩余所有题都是坏题。表格典型场景改成“部分测试脚本或题目有缺陷”，保留污染与错题的区分。
- 多个模型算出一致结果只是触发专家复核的线索，不直接证明参考答案错。删除“只有等所有智能体远超任务才会查出”的必要条件，保留化学模拟造假难验证的例子。
- “指数级上升”未有定量依据，改成复核更费时。工作量证明是嘉宾举例的过程记录设想，非已部署标准；12小时不写成普适制度。
- 时薪100到200美元为孙一铀在节目中的观察及其对高端专家招募的判断，不能写成任何这一区间薪酬都天然招不到顶尖人。正文和列表/框同步。
- 第六章表格保持三列“问题/影响/处理”，减少过长单元格，读者能一眼比较污染、错题、伪造三类差异。
